# 03 · SpecSheet：把一张表写成能编译的东西

> 这一章给出格式、字段含义、以及每个字段填错时的具体后果。
> 契约文件在 `spec/schema/specsheet.schema.json`，本文与它必须一致——不一致时以 schema 为准，并且应该提 issue 改本文。

---

## 一、核心约定：人只做「指认」

SpecSheet 里**不写坐标、不写旋转矩阵、不建拓扑**。

这是整个设计最不可让步的一条。理由：

- 坐标是**计算结果**，不是输入。人填坐标，等于让填表的人手工解一遍装配方程，算错了看不出来。
- 关系是**输入**。人填「减速头与电机同轴」「法兰贴住机身端面」，编译器负责把这些关系解成世界变换。

> 所以这份文件里出现的每个数，要么是**尺寸**（能被验证），要么是**关系**（能被求解）。
> 凡是「这个东西放在哪」的问题，一律不填，交给 `assembly`。

---

## 二、一份最小可编译的 SpecSheet

复制这份，改掉内容就能跑。字段一个不少，也没有一个是多余的。

```yaml
spec_version: "0.1"
id: nema23-actuator          # ^[a-z0-9][a-z0-9-]{1,40}$
title: NEMA23 行星减速执行器
subtitle: 步进电机 + 10:1 行星减速头 · 装配确认件
units: mm

source:
  image: spec/examples/nema23-actuator.png
  grade: R1                  # R1 工程图 / R2 多视角 / R3 单照片 / R4 草图 / R5 纯文字
  note: 外廓与孔位取自规格书三视图；内部轮系按 10:1 反推

intent:
  object: NEMA23 步进电机 + 单级行星减速头
  purpose: 确认装配顺序、轴向总长、安装孔位与减速比
  audience: 有基础            # 外行 / 有基础 / 专业
  scale: "1:1"
  must: [电机机身, 前端法兰, 减速头, 输出轴, 安装底板, 行星轮系]
  drop: [绕组, 编码器, 线缆, 螺纹牙型, 表面涂装]
  delivery: D1

parts:
  - uid: motor_body          # ^[a-z][a-z0-9_]*$
    label: 电机机身
    kind: revolve            # revolve / extrude / gear / pattern / primitive
    axis: x
    material: anodized_black
    params:
      segments: 72
      profile:               # [半径, 轴向]，局部坐标从 0 起
        - [0, 0]
        - [25.0, 0]
        - [25.0, 3.0]
        - [28.575, 3.0]
        - [28.575, 56.0]
        - [0, 56.0]
    evidence:
      机身长:   { value: 56.0,  src: "图注 A1",     grade: measured }
      机身直径: { value: 57.15, src: "NEMA23 标准", grade: standard }
    explode: [-1.0, 0, 0]

assembly:
  - type: coax               # coax / mate / offset / pattern
    a: motor_flange
    b: motor_body
    note: 法兰与机身同轴
  - type: mate
    a: motor_flange
    b: motor_body
    face: end                # 法兰贴住机身 +X 端面
    offset: 0

views:
  - { id: iso,   kind: iso,   label: 等轴测 }
  - { id: front, kind: front, label: 正视 }
```

编译：

```bash
python3 tools/spec_compile.py spec/examples/nema23-actuator.yaml --out spec/out
```

一条命令出三个产物：`*.html`（可交互确认件）、`*.ir.json`（中间表示）、`*.report.html`（C1–C6 检查报告）。

## 三、字段：为什么是这些，不是别的

### 3.1 `source.grade`：先给输入定级

| 值 | 输入是什么 | 它决定了什么 |
|---|---|---|
| `R1` | 工程图，带标注 | 大部分尺寸可标 `measured`，报告覆盖率会高 |
| `R2` | 多视角照片/渲染 | 尺寸靠比例链推，多数是 `inferred` |
| `R3` | 单张照片 | 只有剪影可信，深度方向全靠补 |
| `R4` | 手绘草图 | 意图可信，数值不可信 |
| `R5` | 纯文字 | 全部 `inferred`，覆盖率 0% 是正常的 |

**这一栏不是装饰**。它让读报告的人在第一秒就知道「该用多严的眼光看这份东西」。

填 `R1` 却拿不出标注图，是这一栏最常见的谎。

### 3.2 `parts[].kind`：五种几何能力

| kind | 用来做什么 | 必填参数 |
|---|---|---|
| `revolve` | 回转体：轴、套、法兰盘、轮毂、杯 | `profile`（[半径, 轴向] 点列） |
| `extrude` | 板件、型材、带孔的平面件 | `outline`（轮廓）+ `depth`，可带 `holes` |
| `gear` | 齿轮、同步带轮 | `teeth` / `module` / `thickness` |
| `pattern` | 阵列：螺栓圈、散热片、栅格 | `source`（被复制的形状）+ `count` + 分布 |
| `primitive` | 垫块、简易体、占位 | `type` + 尺寸 |

**「孔」不是独立基元**，它是 `extrude` 的 `holes` 参数。写 `kind: hole` 会被 schema 拒收——这是设计选择：孔依附于某个实体，单独成件在装配里没有意义。

#### `revolve.profile` 的两个坑

**坑一：绕向决定你看到的是外壁还是内壁。**

`profile` 点列如果按顺时针走，`Lathe` 生成的面法线朝内，你看到的会是远侧的内壁——表现为表面出现斜向条带或色块。

编译器现在会在 `fix_winding()` 里自动纠正，但**你填的时候仍然应该从「轴线上的起点」沿外轮廓走到「轴线上的终点」**，因为自动纠正只在轮廓不自交时可靠。

**坑二：`profile` 的坐标是局部的，从 0 起。**

不要把绝对轴向位置填进去。轴向位置由 `assembly` 求解。

### 3.3 `parts[].evidence`：三档成色

```yaml
evidence:
  机身长:   { value: 56.0,  src: "图注 A1",     grade: measured }
  法兰边长: { value: 57.15, src: "NEMA23 标准", grade: standard }
  轮系模数: { value: 1.5,   src: "按 10:1 反推", grade: inferred }
```

键名是**给人看的名字**，不参与几何计算，只用于报告与定位。所以：

- 写清楚它量的是什么（`机身长` 好过 `L1`）
- `src` 必须能被人核查（图注编号、标准号、或者推断依据）
- `grade` 判错比不填更糟——不填是缺失，判错是谎报

**证明它不是装饰的方法**：编译时 C6 会拿每条 `evidence` 去几何上找落点。找不到就进 `orphans`，报告变黄。你填了一个几何上不存在的数，它立刻会告诉你。

### 3.4 `assembly`：用关系说话

| type | 含义 | 参数 |
|---|---|---|
| `coax` | 两件同轴 | `a`, `b` |
| `mate` | 两个面贴合 | `a`, `b`, `face`, `offset` |
| `offset` | 沿某轴偏移 | `a`, `b`, `offset` |
| `pattern` | 按阵列复制 | `a`, `b`, 分布参数 |

**顺序即装配顺序**。CPU 从上往下解，前面的解决定后面的基准。所以 `assembly` 数组的顺序要按「先装什么、后装什么」排。

这一栏出错的方式最有意思：**它不会报错，只会解出一个错的装配。**

C1（同轴）/ C2（贴合）会抓到一部分：如果约束互相矛盾，残差会超出 0.5 mm 的阈值。但如果你漏写了一条约束，它不会报——因为「没说的关系」和「不存在的关系」在数学上一样。

> **漏约束是这份文件最危险的错误类型**：没有报错，没有警告，几何看起来合理，但装配是错的。
> 唯一的防线是：装配完之后，人眼对着图看一遍顺序。

### 3.5 `views`：预置机位

可选。给了就在页面顶部出现视图切换按钮。

`iso / front / side / top` 四种，取景由编译器按包围盒和面板占比自动计算，不需要填相机参数。

## 四、编译产物与六项检查

| 产物 | 是什么 | 谁看 |
|---|---|---|
| `*.html` | 可交互确认件，单文件 | 客户、评审 |
| `*.ir.json` | 中间表示，几何已展开 | 下游工具、二次开发 |
| `*.report.html` | C1–C6 检查报告 | 交付前自己看 |

| 检查 | 判据 | 不过说明什么 |
|---|---|---|
| C1 同轴 | 所有 `coax` 约束的横向偏移 ≤ 0.5 mm | 装配约束写错，或某件 profile 不对称 |
| C2 贴合 | 所有 `mate` 的间隙 ≤ 阈值 | `offset` 填错，或 `face` 指错端 |
| C3 孔位在轮廓内 | 孔洞不越界 | `holes` 的 `at` 偏移漏填（会全堆到原点） |
| C4 包围盒干涉 | 无未声明干涉 | 某件尺寸填大，或装配顺序反了 |
| C5 证据覆盖率 | 可信占比 ≥ 60% | 推断项太多，该去补图或补规格书 |
| C6 证据定位率 | 已定位占比 ≥ 70% | 有数字在几何上找不到，说明填的和建的对不上 |

**C3 和 C6 是最有价值的两个。**

- C3 抓的是「静默忽略」：`expand_shape` 曾经吞掉 `at` 字段，导致所有孔堆在原点，而 C3 永远通过。**静默忽略字段比报错危险得多。**
- C6 抓的是「自己骗自己」：`壳体长` 表里填 45、几何实际 46，两个数字都不假，只是不一致。C6 第一次跑通就报出了这个——**工具抓到了自己的错**。

## 五、填错自查

| 症状 | 病因 | 去哪改 |
|---|---|---|
| schema 校验失败 `additionalProperties` | 多写了字段（比如 `position`） | 删掉；位置归 `assembly` |
| 编译报 `unknown kind` | 写了 `hole` / `box` 之类 | 用 `extrude` + `holes`，或 `primitive` |
| 模型一片黑/条纹 | `profile` 绕向反了，或自交 | 从轴线起点沿外轮廓走到轴线终点 |
| 所有孔都在中心 | `holes[].at` 没生效 | 确认 `at` 写在每个孔对象里 |
| 报告黄条，orphans 有值 | 填的数在几何上找不到 | 二选一：改几何，或改数；**不要调容差** |
| 装配解出来错位 | 漏了 `coax` 或 `mate` | 补约束；不会报错，只能靠人眼对图 |

# 05 · 诊断：症状 → 域 → 根因 → 补丁

> 这一章来自两种经验：原始案例包的 13 条故障码，以及本项目自己踩过的坑。
> 后者更具体，因为它们都有现场。

---

## 一、诊断纪律：不倒推代码，倒推系统

看到结果不对，人的第一反应是去改那行代码。这个反应通常是错的。

**正确顺序**：

1. **定位域**——这是证据/几何/交互/渲染/工程哪一类的问题？
2. **反推缺失的约束**——这个域里，哪一条本该存在而没存在？
3. **补接口**——不是改字，是补系统。改字会让同类问题在别处重演
4. **回归**——改完把整个门禁重跑一遍，因为补接口常会牵动别处

> 一个反例：尺寸线位置不对，直接去调那几行坐标，调好了。
> 下次换一个件，同样的问题又来。根因是「偏移量按全局最大尺寸算」，这是结构问题，改坐标只是在给这一件打补丁。

## 二、证据域：报告在撒谎

这一域最危险，因为**它不产生可见的错误**，只产生一份看起来很专业的错报告。

### `EVD-001` 把推断说成实测

| | |
|---|---|
| **症状** | 报告覆盖率很高，但拿给同行看，对方说「这个数图上是没有的」 |
| **根因** | `grade` 判定时用了「看起来差不多」而非「能圈出起止点」 |
| **补丁** | 逐条重判：圈不出的全部降为 `inferred`。覆盖率会掉，掉到真实位置 |
| **为什么必须修** | 这是整个产品唯一的存在理由。错标一次，报告从此不可信 |

### `EVD-002` 定位失败但被容差掩盖

| | |
|---|---|
| **症状** | C6 报「全部已定位」，但某条尺寸的落点明显指错了地方 |
| **根因** | 容差放宽到 5% 时，`孔分布圆 ⌀62` 会误配到邻近档的法兰外径 70 |
| **补丁** | 容差钉死 `max(0.8 mm, 2%)`；落不上就报未定位，**不做就近吸附** |
| **教训** | 容差放宽的代价不是漏报，是误报 |

### `EVD-003` 无量纲参数被算进分母

| | |
|---|---|
| **症状** | 齿数、模数、减速比被列为「未定位」，覆盖率永远上不去 |
| **根因** | 它们是生成几何的**输入**，不是可测量的**结果** |
| **补丁** | 加 `is_param()` 排除，单独列在报告的「参数」区 |

## 三、几何域：模型长错了

### `GEO-001` 方块感

| | |
|---|---|
| **症状** | 曲面看着像拼起来的盒子，转折生硬 |
| **根因** | 用 Box 拼主体，缺放样/倒角/分段 |
| **补丁** | 流线硬表面改截面放样（Catmull-Rom）；板件加 bevel；回转体用 Lathe 真实截面；补法线平滑 |

### `GEO-002` 表面出现斜向条带或色块

| | |
|---|---|
| **症状** | 回转体表面有规则斜纹/马赛克，位置随视角变 |
| **根因** | 轮廓绕向反了，外壁变成背面，你看到的是远侧内壁 |
| **补丁** | `fix_winding()` 自动纠正，或手工把 profile 从轴线起点沿外轮廓走到轴线终点 |
| **注意** | 自动纠正只在轮廓不自交时可靠 |

### `GEO-003` 所有孔堆在原点

| | |
|---|---|
| **症状** | 孔全在中心，C3「孔位在轮廓内」永远通过 |
| **根因** | `expand_shape` 静默吞掉了 `at` 偏移字段 |
| **补丁** | 在展开时应用偏移；**任何「静默忽略未知字段」的实现都要改成报错** |
| **教训** | 静默忽略字段比报错危险得多——报错会被看见，忽略不会 |

### `GEO-004` 装配解出来错位，但不报错

| | |
|---|---|
| **症状** | 各件都在，但位置关系不对；C1/C2 也可能全绿 |
| **根因** | 漏写了一条 `coax` 或 `mate`。**「没说的关系」和「不存在的关系」在数学上一样** |
| **补丁** | 对着图重排 `assembly` 顺序，逐条补关系 |
| **唯一防线** | 人眼对图。这个错没有自动检查能抓 |

## 四、交互域：点了没反应，或反应错了

### `INT-001` 点到空白处也点亮零件

| | |
|---|---|
| **症状** | 鼠标放在什么都没有的地方，某个零件被高亮 |
| **根因** | `Raycaster.params.Line.threshold` 默认 1 **世界单位**，而毫米制场景模型只有 0.145 m |
| **补丁** | 阈值按模型尺寸缩放（`maxDim * 0.008`），并且只认实体面（`o.object.isMesh`） |
| **为什么难查** | 代码完全正确，错的是单位制与世界尺度的关系 |

### `INT-002` 两侧状态不同步

| | |
|---|---|
| **症状** | 3D 高亮了但面板没变，或反过来 |
| **根因** | 两处各存一份状态 |
| **补丁** | 单一数据源驱动，UI 只读不写 |

### `INT-003` 越用越卡

| | |
|---|---|
| **症状** | 切换几次视图后帧率下降 |
| **根因** | 每次切换新建 `requestAnimationFrame` 循环或事件监听 |
| **补丁** | 循环与监听只在初始化建一次；`dispose` 旧资源 |
| **测法** | 连续切 10 次，看控制台是否刷屏、帧率是否衰减 |

## 五、渲染域：看着廉价

### `MAT-001` 塑料感

| | |
|---|---|
| **症状** | 金属件看着像塑料，反射死板 |
| **根因** | 单一材质、无粗糙度变化、无环境反射 |
| **补丁** | `MeshPhysicalMaterial` + clearcoat + 程序化 roughnessMap；PMREM 环境烘焙 |

### `MAT-002` 曲面出现色块/马赛克

| | |
|---|---|
| **症状** | 曲面上有块状色斑，随镜头变化 |
| **根因** | 渐变 equirect 环境图横向只有十几像素，低 mip 采样被放大 |
| **补丁** | 用 `PMREMGenerator.fromScene()` + 真实柔光棚几何（几个发光面板），不用低分辨率渐变图 |

### `LIT-001` 平光

| | |
|---|---|
| **症状** | 全场景均匀亮，无立体感 |
| **根因** | 只有环境光，缺 key/fill/rim |
| **补丁** | 三点光 + 底部反射光；暗部不死黑，亮部不过曝 |

### `LIT-002` 曲面自阴影出现斜纹

| | |
|---|---|
| **症状** | 零件表面有规则条纹，像扫描线 |
| **根因** | 零件之间互相接收阴影 |
| **补丁** | 零件 `receiveShadow = false`，地面保留 |

### `DIM-001` 标注压在模型上

| | |
|---|---|
| **症状** | 二十几条尺寸线全挤在模型表面 |
| **根因** | 偏移量按全局 `maxDim` 比例算，对细长件太小 |
| **补丁** | 按该构件包围盒在偏移方向上的投影算 `reach`，再按朝向分桶统一排布 |

### `DIM-002` 同侧标注高低不齐、互相压

| | |
|---|---|
| **症状** | 同一侧的几条线间距不等，有的重叠 |
| **根因** | 每件各自外推，没有统一基准 |
| **补丁** | 先收集全部标注，按朝向分桶，每桶取最大 reach 后按序号递增排布 |

### `DIM-003` 选中了但看不出选中

| | |
|---|---|
| **症状** | 点了零件，标注「亮」了但看不出来 |
| **根因** | 深色底上 1px 细线只调 `opacity` 不够 |
| **补丁** | 换暖白色（`0xffe4b8`），取消时按记录的 baseColor 恢复 |

### `CAM-001` 正视时模型被裁

| | |
|---|---|
| **症状** | 切到正视，模型左右各缺一块 |
| **根因** | 取景没按角点深度算；右面板导致左右可用宽度不等 |
| **补丁** | 按每个角点的深度单独求所需距离，并区分 `(1±k)` 的不对称半宽 |

## 六、工程域：交付不了

### `ENG-001` 打开白屏

| | |
|---|---|
| **症状** | 双击 HTML 全白，控制台报 `Failed to resolve module specifier` |
| **根因** | 单文件内嵌时，同一依赖被 import 与 re-export 各一次，第二次仍自增编号，产出未注册的 specifier |
| **补丁** | 命中 `seen` 时复用已注册的 specifier |
| **测法** | `--self-test`，并且必须包含「同一依赖被引用两次」的样本——只测单次依赖会恰好绕开这个缺陷 |

### `ENG-002` 打包体积异常

| | |
|---|---|
| **症状** | D1 产物超过 5 MB |
| **根因** | vendor profile 选了 `full`，把所有 addon 都打进去了 |
| **补丁** | 降到 `standard` 或 `core`，按实际用到的 addon 裁剪 |

## 七、补丁库：改哪里，不改哪里

补丁的原则：**只升目标层，保留既有功能**。重写整体是最后手段，因为它会带回已经修好的老问题。

### 补丁 A · 质感不够（功能可用但廉价）

> 当前版本功能可用，但视觉质感不够。**不要重写业务逻辑**，只升级渲染层与建模层：
> 1. 建模：流线硬表面改截面放样 + bevel；提高关键分段；开孔做凹陷不穿插；回转体用 Lathe 真实截面
> 2. 材质：`MeshPhysicalMaterial` + clearcoat + 程序化 roughnessMap；发光件 emissive + Bloom
> 3. 灯光：三点光 + 底部反射；暗部不死黑
> 4. 后期：ACES + 克制 Bloom + 轻暗角；**不加颗粒与色差**（会干扰尺寸线读数）
> 5. 环境反射：PMREM + 柔光棚几何，不依赖外部 HDRI
> 6. 保持现有功能：不删视图/爆炸/剖切/联动

### 补丁 B · 标注读不清

> 只改标注层：按朝向分桶重排偏移；同值去重；选中换暖白；拆解/剖切态隐藏标注层。不动几何与材质。

### 补丁 C · 报告对不上页面

> 检查报告与页面是否读同一份 IR。若两处各自计算构件数与覆盖率，改为单一数据源。

### 补丁 D · 拾取/相机手感

> 只调 `Raycaster` 阈值与取景距离计算。不动场景内容。

## 八、什么时候该停

有一种情况，继续修是错的：**当问题出在输入，而不是实现。**

症状：C6 的 orphans 一直有值，改了几何还是对不上。

这时候不要继续改代码——去问填表的人：这个数，到底是量什么的？

> 「壳体长填 45、几何 46」那次，两个数字都不假，只是不一致。
> 后来发现是图注 A1 标的是「含端盖 46」、表里填的是「不含端盖 45」。
> **问题不在代码，在语义。**

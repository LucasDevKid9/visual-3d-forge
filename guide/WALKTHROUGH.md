# 走通一遍：从一张规格书到一份能交的确认件

> 这是 NEMA23 行星减速执行器的真实记录，包括**填错的那几版**。
> 完整产物在 [`../spec/out/nema23-actuator.html`](../spec/out/nema23-actuator.html)，源文件在 [`../spec/examples/nema23-actuator.yaml`](../spec/examples/nema23-actuator.yaml)。
>
> 读的时候请注意：下面每一个「后来发现错了」的地方，都不是粗心，是**当时那样想是合理的**。

---

## 起点：手上有什么

- 一张 NEMA23 步进电机的规格书页面（三视图 + 尺寸标注）
- 一段口头需求：「做个减速头的，我要看轴向总长和装配顺序」
- 没有 3D 模型，没有内部结构图

按 [`01-BRIEF.md`](./01-BRIEF.md) 填表，二十分钟，得到：

```yaml
object: NEMA23 步进电机 + 单级行星减速头
purpose: 确认装配顺序、轴向总长、安装孔位与减速比
audience: 有基础
scale: "1:1"
must: [电机机身, 前端法兰, 减速头, 输出轴, 安装底板, 行星轮系]
drop: [绕组, 编码器, 线缆, 螺纹牙型, 表面涂装]
delivery: D1
```

**这一步最关键的一个决定是 `drop`。** 写了「绕组、编码器、线缆」，意味着后面不会有人问「怎么没有绕组」。没写，就意味着要吵一次。

---

## 第一版：能编译，但有一个数在撒谎

第一版填得很顺。机身、法兰、减速头、输出轴，尺寸都能从图上读出来。内部轮系没有图，按 10:1 反推。

编译通过，六项检查全绿。看起来可以交了。

然后 C6 报了一行：

```
[PASS] C6  证据定位率
       26/26 项尺寸已在几何上定位
```

**全过。但这是它第一次跑通时，唯一一次「全过让我不安」。**

因为我知道内部轮系是按 10:1 反推的，反推出来的模数、齿数、中心距，都和几何对得上——**当然对得上，几何就是按这些数生成的**。

这就是「自证」：用自己生成的数去验证自己。C6 在这件事上什么都没证明。真正的证明要看：图上标的那些数，是不是真的落在图上那个位置。

于是把 `壳体长` 单独拎出来量了一遍。

### 错在哪

| | 表里 | 几何实际 |
|---|---|---|
| 壳体长 | 45.0 | 46.0 |

差 1 mm。两个数字**都不假**：图注 A1 标的是「含端盖 46」，表里填的是「不含端盖 45」。填表的人按自己理解的「壳体」来填，建几何的人按图注来建。

C6 报出来的方式是：`壳体长 45` 在几何上找不到落点——因为几何里根本没有 45 这一段。它进了 `orphans`。

> **这是工具抓到了自己的错。**
> 如果 C6 只做「这个数在不在合理范围」，它会放过；正因为 C6 要求「这个数必须钉在某一段几何上，且那一段的长度等于它」，45 就无处可躲。

### 怎么修

二选一，都行，但必须选：

- **改数**：表里改成 46，`src` 注明「图注 A1，含端盖」
- **改几何**：把端盖单独拆成一件，壳体就是 45

选了第一个。理由：目的是「确认装配顺序与总长」，端盖单独成件对这件事没有帮助，反而多一个构件要解释。

**修完之后要重跑全部六项检查**——因为改了数，包围盒变了，C4 干涉和 C2 贴合都可能跟着变。

## 第二版：数字对了，模型长错了

数字对齐之后，打开页面，第一眼就不对。

### 现象一：减速头表面有斜向条带

规则斜纹，转视角时条带跟着动。

查了三轮才发现根因：**回转轮廓的绕向反了**。`Lathe` 要求轮廓逆时针走，顺时针走的话生成的面法线朝内——于是外壁变成了背面，你透过它看到的是**远侧的内壁**。那条带是内壁的明暗交界。

修法：编译期加 `fix_winding()`，按有向面积判断，为负就反转点列。

**为什么值得写进编译器而不是每次手工查**：这个错不报错、不崩溃、几何看起来「大致对」，只是表面脏。人眼很难分辨「脏」和「材质没调好」，会先去调材质，浪费半天。

### 现象二：所有孔堆在原点

法兰上有四个安装孔，配置里写了位置，但渲染出来全在中心。

根因：`expand_shape()` 在把孔的 DSL 展开成多边形时，**静默吞掉了 `at` 偏移字段**。

它不报错。因为对代码来说，「这个字段我不认识」和「这个字段不存在」是一回事。而对填表的人来说，位置写了就是写了。

更糟的是：C3「孔位在轮廓内」永远通过——四个孔都在原点，原点当然在轮廓内。

修法：应用偏移。

> 这一条后来写进了 [`../docs/PRINCIPLES.md`](../docs/PRINCIPLES.md)：
> **静默忽略字段，比报错危险得多。** 报错会被看见，忽略不会。

### 现象三：曲面上有色块

金属件表面有块状色斑，随镜头变。

根因不在材质：环境贴图是一张程序化生成的渐变 equirect 图，横向只有十几个像素。低 mip 层级采样时被放大成色块。

修法：改用 `PMREMGenerator.fromScene()` + 一个真的柔光棚场景（一个暗房盒子 + 四块发光面板）。反射的细节来自几何，不来自贴图分辨率。

## 第三版：模型对了，标注读不了

几何正确之后，加上尺寸线，问题变成另一类。

### 现象四：26 条尺寸线全压在模型上

偏移量是按全局最大尺寸的比例算的。对细长件（输出轴 ⌀8、长 30），`maxDim × 0.06` 只有不到 2 mm，标注几乎贴在表面上。

修法：偏移量按**该构件自己的包围盒在偏移方向上的投影**算。

```js
const reach = Math.abs(ph.x*off.x) + Math.abs(ph.y*off.y) + Math.abs(ph.z*off.z);
```

### 现象五：同一侧的标注高低不齐

改完偏移，新的问题来了：同侧几条线间距不等，有的互相压。

根因：每件各自外推，没有统一基准——短的推得近，长的推得远。

修法：**先收集，再排布。** 按朝向分桶，每桶取最大 reach 作为基准，再按序号递增。

```js
buckets.forEach((arr) => {
  const maxReach = Math.max(...arr.map((sp) => sp.reach));
  arr.forEach((sp, i) => drawDim(sp, maxReach + maxDim * (0.028 + 0.038 * i)));
});
```

### 现象六：鼠标放在空白处也会点亮零件

这个最隐蔽。代码完全正确，错的是**单位制**。

`Raycaster.params.Line.threshold` 默认值是 1，单位是**世界单位**。场景是毫米制，模型总高只有 0.145 m。1 个世界单位 = 145 mm，比整个模型还大。

结果是：全屏都落在描边的命中范围里。

修法两条：阈值按模型尺寸缩放（`maxDim * 0.008`），并且只认实体面（`if (!o.object.isMesh) continue`）。

### 现象七：切到正视，模型左右各缺一块

取景距离是按模型外接球的半径算的。但：

- 透视投影下，不同深度的角点需要不同距离
- 右侧有 340px 面板，导致**左右可用宽度不等**，左边 1 份、右边 0.66 份

修法：按每个角点的深度单独求所需距离，并区分 `(1±k)` 的不对称半宽。

```js
const k = panelRatio();
const needH = cr >= 0 ? cr/(tanH*(1+k)) : -cr/(tanH*(1-k));
need = Math.max(need, Math.abs(c.dot(up))/tanV - depth, needH - depth);
return need * 1.06;   // 留白给标注，不是给模型
```

最后那个 `1.06` 值得单说：留白是为了放尺寸线，不是为了让模型好看。所以包围盒应该按「模型 + 标注外扩」算，而不是按模型算。

## 交付

六项检查：

```
[PASS] C1  同轴          所有 coax 约束的横向偏移为 0（≤0.5 mm）
[PASS] C2  贴合间隙      4 处贴合，最大偏差 0.000 mm
[PASS] C3  孔位在轮廓内  所有孔洞均落在轮廓内，无越界
[PASS] C4  包围盒干涉    无未声明干涉
[PASS] C5  证据覆盖率    可信 67%（实测 11 + 标准 9）/ 共 30 项
[PASS] C6  证据定位率    26/26 项已定位；另 4 项为无量纲参数，不参与定位
```

**覆盖率 67%，不是 100%。** 这是这份交付里最诚实的一个数字：30 项里 10 项是推断，页面上用琥珀色标出来了，报告里列了每一项的推断依据。

如果目标是「报告好看」，这个数可以做到 100%——把 10 个 `inferred` 改成 `measured` 就行。没人会当场发现。

**但那就是另一个产品了。**

## 复盘：哪些是可替换的，哪些不是

要拿这套方法做别的东西时，先分清这两栏。

### 可替换（照抄会做错）

| 这一版里的 | 换主体时 |
|---|---|
| NEMA23 的具体尺寸 | 换掉 |
| 10:1 减速比、行星轮系 | 换掉，或者整件删掉 |
| 「轴向」作为主装配轴 | 换主体后可能是 Y 轴或任意轴 |
| 暗色工业风配色 | 换主体重推 7–8 色，不要粘贴 |
| 26 条尺寸线的排布 | 数量与朝向都会变 |

### 不可替换（这才是要学的东西）

| 结构 | 为什么 |
|---|---|
| 人只填关系，不填坐标 | 一旦让人填坐标，装配错误就不可见 |
| 三档成色，且必须能指出处 | 这是「可被追问」的全部实现 |
| 落点限定五种，落不上就报未定位 | 就近吸附会把误报伪装成通过 |
| 容差 `max(0.8 mm, 2%)` | 放宽的代价是误报，不是漏报 |
| 编译期抓错，不留给眼睛 | 眼睛只能看见「脏」，看不见「错」 |
| 标注在拆解态隐藏 | 零件走了，标注留在原地就是错的 |
| 单一数据源驱动四处联动 | 两份状态必然不同步 |

### 一条元规则

> 判断一个做法该不该抄：**问它「换一个主体还成立吗」。**
> 成立的抄，不成立的自己想。

## 想自己试一遍

```bash
# 1. 复制示例，改成你要的东西（改 scale 表与构件树，不是随手写 mesh）
cp spec/examples/nema23-actuator.yaml spec/examples/my-part.yaml

# 2. 编译
python3 tools/spec_compile.py spec/examples/my-part.yaml --out spec/out

# 3. 看报告，有 orphans 就回去改
open spec/out/my-part.report.html
```

**第一版一定会有 orphans。** 那不是失败，那是这份工具在正常工作——它在告诉你哪个数字还没有着落。

## 一、先把最大的区别说清楚

你问的是：都有 3D，我们和 Blender / C4D / Spline 最大的区别在哪。

不是"我们的渲染差一点"，也不是"我们的建模弱一点"。是三个更根本的差别。

### 差别一：谁在做决定

| | Blender / C4D | Spline | 我们 |
|---|---|---|---|
| 决策者 | **人**，逐个顶点、逐根边 | **设计师**，拖组件调参数 | **规格**，图上的那个数字 |
| 软件的角色 | 手 | 手（更好用的手） | **翻译** |
| 人的技能要求 | 高（要学 300 小时） | 中（要学 30 小时） | **低（会读图就行）** |

Blender 的价值 = 人的时间 × 人的水平。它没法替你决定"这个法兰外径是多少"，因为那不是软件该知道的事。

而我们要处理的场景里，**这个数字已经有人决定过了**——它写在图纸上、写在规格书里、写在客户发来的那张截图上。剩下的不是创作，是**翻译**。

> 一句话：**他们放大人的手艺，我们消灭"翻译"这个动作。**

### 差别二：产物是什么

| | 他们的产物 | 我们的产物 |
|---|---|---|
| 形态 | `.blend` / `.c4d` / `.glb` | 一个 `.html` 文件 |
| 性质 | **资产**——可编辑、可继续加工、没有终点 | **断言**——只读、确定、有终点 |
| 价值 | 后续能改出 100 个版本 | **此刻能被确认** |
| 失败方式 | 不好看 | **不准**（尺寸错、装不上） |

这是最容易被误解的一点。我们交付的东西**不能编辑**，这不是缺陷，是承诺：

- 不能编辑 → 同一个输入永远同一个输出 → 敢签字
- 不能编辑 → 不需要"项目文件" → 发个链接就能看，发个邮件就能存档
- 不能编辑 → 用户不会问"能不能再加个功能" → 需求不会无限膨胀

**资产是给人继续加工用的，断言是给人做决定用的。** 我们卖后者。

### 差别三：站在时间轴的哪一格

这是最要害的一条。任何一个"东西要被造出来"的项目，时间轴是这样的：

```
  概念         规格          【确认】          建模           渲染          交付
   │            │               │               │              │             │
  草图         图纸/参数         ???          Blender         C4D/Arnold    成片
                               ↑
                          这一格是空的
```

- **Blender / C4D 占据「建模 → 渲染」**，工期 2 天到 2 周，报价几千到几万。这是他们的地盘，我们永远打不进去，也不该打。
- **「确认」这一格，目前没有任何工具。** 今天行业里的做法是：
  1. 等建模师排期，3–5 天出一个白模；
  2. 或者用 PPT 画几个方框，配文字说"大概是这样"；
  3. 或者干脆跳过，直接开模，错了再改。

第 3 种做法的代价是**返工**。一次结构返工，成本是建模费的 10 倍以上。

**我们要占的就是这一格。** 它不需要好看，只需要**准确、快、能当场转起来**。

> 所以真正的定位是：**不做模型，做"模型之前的那一次对齐"。**

### 三个词收口

> **他们造模型，我们造共识。**
>
> 模型回答"它长什么样"；共识回答"我们说的是不是同一个东西，这是尺寸，这是间隙，这是你画的那张图"。
>
> **他们卖可能性，我们卖"现在就看得见"。**

## 二、为什么这个位置既安全，又够大

### 安全：三件事模型不会替我们做

| 会被模型吃掉 | 不会被模型吃掉 |
|---|---|
| 写 three.js 代码 | **从图里抽出"160 是外径不是长度"** |
| 猜一个物体大概长什么样 | **让 12 个尺寸互相自洽**（约束满足） |
| 调一个好看的机位 | **说清哪个数字有据、哪个是猜的**（责任归属） |
| 生成一段材质 | **保证同一张图永远出同一版**（确定性） |

左边是"生成"，右边是"担责"。生成能力每年涨，担责能力不会——因为它不是能力问题，是**责任归属问题**。

一个模型可以在 3 秒内给你一个漂亮的齿轮箱，但它不会告诉你"这个箱体的壁厚是我编的"。而客户签收时，恰恰只关心这一句。

### 安全：3D 软件不会下沉到这里

三个理由，都是商业结构决定的：

1. **自我蚕食**。Blender 免费但卖的是生态与培训；C4D 卖的是席位。做一个"3 分钟出确认件、不需要学"的工具，等于告诉客户"你其实不需要买席位"。
2. **组织阻抗**。这类工具的买单方是市场部、销售部、项目部，不是 3D 部门。3D 软件公司没有这条销售通路。
3. **形态冲突**。他们的产品是"重客户端 + 项目文件"，我们的产品是"一个 HTML + 一个链接"。这是两种交付哲学，不是功能差距。

类比：AutoCAD 做了三十年，也没做"看图纸"的 App。看图这件事最后是 Bluebeam、是微信、是 PDF 阅读器做的。

### 够大：一个可直接计价的指标

这个位置有一个罕见的优势——**它能用一个数字说清价值**：

> **TTC（Time to Confirm）：从"把图给对方"到"对方说'对，就是这样'"的时间。**

| 现状 | 目标 |
|---|---|
| 3–5 天（等建模师排期出白模） | **< 30 分钟** |
| 或者 3 小时（会 3D 的人自己搭个方块） | 同上，但不需要会 3D |
| 或者永远没有（跳过确认，直接返工） | 同上，且留下证据 |

这个数字可以写进提案、写进合同、写进复盘。它不需要解释"什么是 PBR"，老板一听就懂。

而 Blender 的销售没法说这个数字——他们卖的是"更强的能力"，不是"更短的时间"。

## 三、产品定义：一条三层的契约

整条链只有三样东西。想清楚这三样，剩下的都是工程。

```
┌─────────────────┐     ┌─────────────────┐     ┌──────────────────┐
│  ① SpecSheet    │     │  ② Spec-IR      │     │  ③ 三件产物       │
│  图 + 标注表     │ ──▶ │  构件/尺度/装配  │ ──▶ │  页面/报告/起稿    │
│  + 意图卡        │     │  + 证据链        │     │                  │
└─────────────────┘     └─────────────────┘     └──────────────────┘
     人填 30 分钟            编译器求解              打开即用
```

### ① 输入契约：SpecSheet（人只做"指认"，不做"建模"）

一份 YAML（也接受 JSON），四块：

```yaml
source:                    # 图从哪来，可信到什么程度
  image: drawing.png
  grade: R1                # 复用 R1–R5 分级
  unit: mm

intent:                    # 复用意图卡七字段，一个不少
  object: 单级齿轮减速器 R40
  purpose: 确认装配关系与外廓尺寸
  audience: 有基础
  scale: 1:1
  must: [输入轴, 输出轴, 箱体, 齿面啮合]
  drop: [润滑油路, 螺栓倒角]
  delivery: D1

parts:                     # 构件表：人只写"这是什么 + 几个数"
  - id: housing
    kind: revolve          # 五个基元之一
    profile: [[0,0],[80,0],[80,120],[0,120]]
    dims: {外径: 160, 长: 120}
    evidence: {外径: A2, 长: A3}     # 这个数图上的哪个标注

assembly:                  # 装配意图：用约束说，不用坐标说
  - {type: coax, a: shaft_in, b: gear_1}
  - {type: mate, a: bearing_in, b: housing, face: inner}

views:                     # 要看哪几个角度、要不要剖
  - {id: hero, kind: iso}
  - {id: cut,  kind: section, axis: z, at: 0}
```

**关键设计**：人不写坐标，只写关系。坐标由编译器解。

这是它和"拖拽建模"最本质的分野：拖拽的人在做几何，写约束的人在做**意图**。意图可复现，几何不可复现。

### ② 中间表示：Spec-IR（编译器唯一的真相）

```jsonc
{
  "ir_version": "0.1",
  "units": "mm",
  "parts": [{
    "uid": "housing@a3f1",          // 稳定 ID，不是数组下标（L2 回写的前提）
    "kind": "revolve",
    "params": { "profile": [...], "segments": 64 },
    "transform": { "pos": [0,0,0], "rot": [0,0,0] },   // 由约束求解得出
    "material": "cast_iron",
    "evidence": {                    // 证据链：每个数字都能追溯
      "外径": { "value": 160, "src": "A2", "grade": "measured" },
      "长":   { "value": 120, "src": "A3", "grade": "measured" },
      "壁厚": { "value": 8,   "src": "先验:铸件最小壁厚", "grade": "inferred" }
    }
  }],
  "assembly": { "solved": true, "conflicts": [] },
  "report": { "checks": [ ... ] }
}
```

`grade` 三档，是整个产品的灵魂：

| 成色 | 含义 | 产物里的表现 |
|---|---|---|
| `measured` | 图上有明确标注 | **绿色实线** + 悬停显示"图注 A2" |
| `inferred` | 按比例/对称/先验推的 | **琥珀虚线** + 悬停显示推断依据 |
| `standard` | 标准件（GB/ISO） | **灰色** + 显示标准号 |

> **没有任何一个竞品会告诉用户"这个数字是我猜的"。**
> 因为他们的商业模式建立在"看起来专业"上；我们的商业模式建立在"敢签字"上。
> 这就是为什么这一条必须做，而且必须做到视觉上一眼可辨。

### ③ 输出契约：三件东西，三种用途

| 产物 | 给谁 | 解决什么 |
|---|---|---|
| **确认页** `.html`（单文件，离线可开） | 客户 / 老板 / 销售 | 30 秒看懂，能转、能剖、能量 |
| **一致性报告** `.html` + `.json` | 项目 / 质量 | 哪些数对上了，哪些是推断，误差多少 |
| **起稿** `.glb` | 建模师 | 不用从零开始，改细节就行 |

第三件是"打辅助"的物理证明：**我们不是替代建模师，我们给他送一个已经对了 70% 的起点。**

## 四、技术核心：五个基元 + 一台求解器

这是"能兑现承诺"和"吹牛"的分界线。通用建模我们做不了，也不做。我们只做**机加工/产品件里占 80% 的五类形体**：

| 基元 | 覆盖什么 | 实现 |
|---|---|---|
| `revolve` | 轴、套、法兰、轮毂、端盖、箱体回转段 | `LatheGeometry` + 轮廓表 |
| `extrude` | 板件、支架、型材、壳体侧壁 | `ExtrudeGeometry` + 轮廓 + 厚度 |
| `gear` | 直齿/斜齿/内齿 | 已有参数化齿形（Willis 求解复用） |
| `pattern` | 螺栓孔、散热片、齿圈阵列 | `InstancedMesh` |
| `hole` | 通孔/沉孔/螺纹底孔（以剖面表达） | CSG 替代：几何预留 + 剖切显示 |

**为什么是这五个**：因为它们全部由"一张轮廓 + 一组标量"决定。轮廓可以从三视图描出来，标量就是图上那些数字。**没有一个需要人做拓扑编辑。**

### 求解器：尺寸一致性 + 装配约束

两个求解，都是小而确定的问题：

1. **尺度自洽**：给定若干标注和"同轴/贴合/对称"关系，检查是否矛盾（例如"总长 120 = 段1 60 + 段2 60 + 端盖 2×6"不成立就报红）。
2. **装配定位**：`coax`（同轴）、`mate`（面贴合 + 偏移）、`pattern`（阵列）三种约束，做一遍拓扑排序求解世界变换，冲突则报出冲突对。

这两个都不需要 AI，也不该用 AI。**它们是可以被写成单元测试的东西**，而可测试 = 可承诺 = 可计价。

### 降级诚实：图不够的时候怎么办

| 图的情况 | 我们做什么 | 页面上怎么表现 |
|---|---|---|
| R1 三视图带标注 | 全测量，误差 < 1% | 全部绿线 |
| R2 多视角照片 | 主尺寸测量，深度推断 | 主视绿、厚度琥珀 |
| R3 单张照片 | 只保证比例关系，绝对尺度靠先验 | 顶部横幅："绝对尺寸为推断，比例可信" |
| R4 草图 | 只做形体示意 | 全部琥珀 + "示意，非实测" |
| R5 纯文字 | 走原有意图→IR 通道 | 标注"无参考图" |

**这条表的用途不是免责，是定价。** R1 的活可以卖 10 倍于 R4 的价，因为可承诺的东西不一样。

## 五、26 周：四个阶段，每阶段一个可证伪判据

原则：**判据不达标，不进入下一阶段。** 宁可少做一个阶段，不要四个都半成品。

### P0 · W1–W4｜把入口换掉：从"一句话"到"图 + 表"

**目标**：证明"人填表 → 机器出页面"这条路在工程上成立，且**完全不依赖大模型**。

| 周 | 任务 | 交付物 | 完成标志 |
|---|---|---|---|
| W1 | 定 SpecSheet schema + IR schema | `spec/schema/*.schema.json` | 两个 schema 能被 `jsonschema` 校验通过 |
| W1 | 建五个基元的运行时 | `spec/runtime/geometry.js` | 每个基元能独立渲染出正确形体 |
| W2 | 装配求解器（coax/mate/pattern） | `spec/runtime/assembly.js` | 10 个装配用例全部解出，冲突用例能报错 |
| W2 | 编译器 CLI：YAML → IR → HTML | `tools/spec_compile.py` | 一条命令出单文件页面 |
| W3 | 证据链着色 + 悬停溯源 | `spec/runtime/evidence.js` | 绿/琥珀/灰三档在页面上可辨 |
| W3 | 一致性报告生成 | 报告 HTML/JSON 模板 | 每个尺寸有"标注 vs 实测 vs 误差" |
| W4 | 三个真实案例 | `spec/examples/*.yaml` | 减速器 / 法兰支架 / 型材框架 |

**判据**：找一个没参与开发的人，给他一张标注图 + 一张空表，**30 分钟内**产出一版能转的页面，且**外廓尺寸误差 < 2%**。

**不做**：不做图片自动识别（P2 才做）、不做材质真实感、不做动画。

> 这一阶段的意义：先把"确定性"这条路走通。如果 P0 都做不到 30 分钟，后面全部免谈。

### P1 · W5–W10｜证据链：让每个数字都能被追问

**目标**：从"看起来对"升级到"说得清为什么对"。

| 周 | 任务 | 交付物 | 完成标志 |
|---|---|---|---|
| W5 | 标注表 → 图上的定位（手工框选 + 坐标存储） | `spec/annotate.html`（本地标定工具） | 点一条标注，图上高亮对应箭头 |
| W6 | 尺度自洽求解（线性方程组 + 冲突检测） | `solver/scale.py` | 矛盾输入必须报红并指出冲突项 |
| W7 | 报告升级：证据覆盖率指标 | 报告新增「measured/inferred 占比」 | 覆盖率 < 60% 时页面顶部黄条警告 |
| W8 | 剖切系统（轴向/径向/任意平面） | `spec/runtime/section.js` | 剖切后内部结构正确显示，无 z-fighting |
| W9 | 测量交互（点两点出尺寸，与标注比对） | 页面内 measure 工具 | 用户自己量出的数与报告一致 |
| W10 | 五个案例回归 + 报告归档 | `spec/regression/` | 5 个案例重编译，产物哈希稳定 |

**判据**：随机抽 20 个尺寸送到第三方核对来源，**"把推断说成测量"的错误必须为 0**。允许漏标，不允许错标。

**不做**：不做自动 OCR（还没到时候）、不做多人协作。

> 这一阶段的意义：**认知诚实必须产品化，否则它就只是一句口号。**

### P2 · W11–W18｜半自动反演：图 → 基元建议

**目标**：把"人填表"从 30 分钟压到 5 分钟。注意是**建议**，不是自动生成。

| 周 | 任务 | 交付物 | 完成标志 |
|---|---|---|---|
| W11 | 图纸预处理：去噪、矫正、比例尺检测 | `vision/preprocess.py` | 倾斜 15° 内自动矫正 |
| W12 | 轮廓提取（Canny + 直线/圆弧拟合） | `vision/contour.py` | 三视图轮廓闭合率 > 90% |
| W13 | 基元分类器（回转 vs 拉伸 vs 阵列） | `vision/classify.py` | 50 个样本 top-1 准确率 > 70% |
| W14 | 尺寸标注 OCR + 箭头配对 | `vision/annotate.py` | 数字识别准确率 > 90%，箭头配对 > 80% |
| W15 | 反演结果 → 预填 SpecSheet（人确认） | 前端"建议面板" | 每个建议可accept/reject，reject 记日志 |
| W16 | 反馈闭环：reject 样本进训练集 | `vision/feedback.py` | 每周自动重训一次 |
| W17 | 三视图对齐（正/俯/侧投影一致性） | `vision/views.py` | 三个视图反推的同一尺寸偏差 < 3% |
| W18 | 端到端：图 → 建议表 → 页面 | demo 视频 | 从上传到出页 < 5 分钟 |

**判据**：50 个真实零件图上，**一次通过率 > 50%，两次内 > 85%**。

**不做**：不做通用 CAD 逆向（scan-to-CAD）、不做自由曲面。

> 这一阶段的意义：把人从"填 40 个数"降到"改 8 个数"。**降低门槛，而不是取消人。**

### P3 · W19–W26｜起稿：让建模师愿意接过去

**目标**：证明我们进得了别人的管线，而不是另起一个孤岛。

| 周 | 任务 | 交付物 | 完成标志 |
|---|---|---|---|
| W19 | glTF 导出（PBR + 层级 + 尺度 1:1） | `spec/export/gltf.js` | Blender 打开，包围盒误差 < 1% |
| W20 | 材质映射表（IR 材质 → glTF PBR） | `spec/export/materials.json` | 8 种常用材质双向一致 |
| W21 | `ir2blend.py`：IR → Blender 场景 + 命名规范 | `spec/bridge/ir2blend.py` | 每个构件名 = `uid`，可被脚本找回 |
| W22 | `blend2ir.py`：改完回写（材质/尺寸） | `spec/bridge/blend2ir.py` | 改一个颜色，重编译页面能看见 |
| W23 | USD 最小子集（Xform/Mesh/Material 三层） | `spec/export/usd.py` | `usdchecker` 通过 |
| W24 | 与一位真实建模师做联合测试 | 测试记录 | 他的原话进 README |
| W25 | 交付包生成器（页面 + 报告 + glb + 说明） | `tools/deliver.py` | 一个 zip，四个文件，双击可用 |
| W26 | 对外文档 + 案例页 | Gallery 上线 | 陌生人 30 秒内说出"这是干嘛的" |

**判据**：建模师拿到起稿，从"开始"到"可渲染"的时间，比自己从零建模**缩短 > 40%**。这条必须由他自己计时，不能由我们估算。

**不做**：不做双向实时同步、不做 C4D/Houdini 适配（先做一个，做透）。

## 六、四个风险，和对策

### 风险 1：被当成"低配版建模软件"

**表现**：客户问"能不能改一下这个圆角"，你说不能，他觉得你残废。

**对策**：话术和产品都要提前分流。
- 页面上明确写「这是确认件，不是模型。要改，点这里导出给建模师」。
- 导出按钮放在最显眼的位置——**主动把"改"这件事交出去**，这是辅助定位的姿态。

### 风险 2：图纸质量差，做不出来

**表现**：客户发来一张手机拍的模糊照片，你出的东西不像，口碑崩。

**对策**：R 分级前置。上传时就让用户选"这是什么级别的图"，选 R3/R4 就自动切到"示意模式"，页面顶部横幅写明。**不接做不到的活，比接了做砸强。**

### 风险 3：五基元覆盖不了

**表现**：客户要一个有机曲面外壳（鼠标、头盔、鞋），五基元拼不出来。

**对策**：明确"体外循环"。这类需求直接回："这部分建议进 Blender，我们可以把尺寸和约束给你"。**边界清晰反而是专业信号。**

### 风险 4：没人愿意填表

**表现**：SpecSheet 有 40 个字段，用户看一眼就关了。

**对策**：三条。
1. 必填字段压到 6 个（object / image / unit / 3 个主尺寸），其余全部可推断。
2. P2 的反演就是为这件事准备的——**长期看，表应该是机器填、人改**。
3. 提供 20 个模板（法兰、支架、轴、箱体…），选模板比填表快 10 倍。

## 七、北极星与阶段性指标

| 指标 | 定义 | P0 目标 | P3 目标 |
|---|---|---|---|
| **TTC** | 给图 → 客户确认 | 30 min | **8 min** |
| **一次通过率** | 无返工直接确认的比例 | 40% | **75%** |
| **证据覆盖率** | measured 尺寸 / 总尺寸 | 60% | **85%** |
| **尺寸误差** | 外廓实测 vs 标注 | < 2% | **< 0.5%** |
| **起稿省时** | 建模师省下的时间占比 | — | **> 40%** |

**最该盯的是 TTC 和一次通过率。** 前者决定客户要不要用，后者决定客户会不会再用。

## 八、一页纸

| 问题 | 结论 |
|---|---|
| **和 Blender/C4D 最大的区别** | 他们放大人的手艺，我们消灭"翻译"这个动作 |
| **我们卖什么** | 不是模型，是**共识**——"现在就看得见" |
| **占哪个位置** | 项目时间轴上「确认」那一格，建模之前，渲染之外 |
| **产物是什么** | 确认页（HTML）+ 一致性报告 + 给建模师的起稿（glb） |
| **技术上靠什么** | 五个基元 + 一台约束求解器 + 一条证据链。**不用大模型也能跑** |
| **最独特的一件事** | 告诉用户"这个数字是我猜的"，并且视觉上一眼可辨 |
| **26 周做什么** | 入口（W1–4）→ 证据链（W5–10）→ 半自动反演（W11–18）→ 起稿导出（W19–26） |
| **不做什么** | 不做编辑器、不做渲染器、不做通用建模、不做有机曲面 |
| **怎么计价** | 按 R 分级定价：R1 的活卖 10 倍于 R4 |

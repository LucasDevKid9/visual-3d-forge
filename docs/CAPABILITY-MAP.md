# three.js 能力地图：620 个示例，我们取哪几个

> 这份文档回答一个问题：**three.js 官方示例库有 620 个 demo，我们为什么不全都做，以及我们到底该做哪几个。**
>
> 它是一次**拒绝的记录**，不是一份愿望清单。每一条「不取」都附理由，
> 因为一个什么都做的确认件，等于什么都没做深。

抓取时间：2026-11-18，`threejs.org/examples/` 页面实测 620 条。

---

## 一、库的构成

| 分类 | 数量 | 占比 |
|---|---:|---:|
| webgpu | 243 | 39% |
| webgl | 221 | 36% |
| webgl / advanced | 48 | 8% |
| webxr | 27 | 4% |
| webgl / postprocessing | 26 | 4% |
| misc | 22 | 4% |
| physics | 13 | 2% |
| css3d | 6 | 1% |
| webaudio | 4 | 1% |
| webgl / tsl | 4 | 1% |
| svg / css2d / games / tests | 6 | 1% |

**39% 是 WebGPU。** 这一条就决定了我们不可能「跟一遍」：
确认件的硬约束是**单文件、双击能开、断网能跑**，
而 WebGPU 在 2026 年的桌面浏览器覆盖率仍不足以作为默认路径。

## 二、逐类判定

判定分三档：**取**（进入产品）／**借**（只借思路，不引代码）／**不取**（写明理由）。

| 分类 | 判定 | 取什么 / 为什么不取 |
|---|---|---|
| `webgl`（221） | **取一部分** | 只取五组：材质、几何、阴影、光照、交互拾取。动画、骨骼、蒙皮、粒子、水、天空盒全部不取 |
| `webgl / postprocessing`（26） | **取 3 个** | GTAO（环境光遮蔽）、SMAAPass（抗锯齿）、自定义淡入。景深、故障、godrays、3DLUT、afterimage 不取 |
| `webgl / advanced`（48） | **取 2 个** | instancing（阵列特征：一圈 24 个螺栓孔）／drawRange。其余是底层 buffer 实验，与确认件无关 |
| `webgl / tsl`（4） | **不取** | TSL 是 WebGPU 的着色器语言，走这条路等于放弃离线单文件 |
| `webgpu`（243） | **不取** | 见第一节。等覆盖率过线再做，不做「演示能用、客户打不开」的功能 |
| `webxr`（27） | **不取** | AR 是确认件的终局形态（把件摆到客户桌上），但不是今年的活。现在做等于把资源押在一个还没有销售通路的形态上 |
| `webaudio`（4） | **不取** | 一份拿去签字的工程文件，配了音效之后评审会第一个问题会变成「这音乐能关吗」。判定过程见 [`../guide/06-EXPERIENCE.md`](../guide/06-EXPERIENCE.md) |
| `physics`（13） | **不取** | 确认件是静态几何。装配关系由约束求解器管（同轴/贴合/对称），不需要刚体。上物理引擎会把「这个件装不上」变成「这个件掉下来了」，语义全错 |
| `games`（1） | **不取** | — |
| `misc`（22） | **借** | 取 `misc_controls_*` 的阻尼参数手感，不引代码 |
| `css2d` / `css3d`（7） | **不取** | 我们用手写 DOM 做了更贴合的版本：标注要参与排版、要能着色、要能被键盘遍历。CSS2DRenderer 给不了这三样 |
| `svg`（2） | **不取** | — |
| `tests`（2） | **不取** | 是 three 自己的回归页 |

**结论：620 个里，进产品的上限是 10 个左右。** 剩下的 610 个不是「还没做」，是「不该做」。

## 三、这一轮实际拿走的四件事

### 1. 接触阴影（`webgl_shadow_contact`）

产品照里唯一的阴影，是物件正下方那一团。斜射主光会在台面上拖出一条有硬边、
有方向的长影——观众第一眼读到的是「几点钟的太阳」，不是「这个件多大」。

实现要点（三条都是被真实渲染逼出来的）：

| 坑 | 现象 | 解法 |
|---|---|---|
| 地面用 `ShadowMaterial` | 影子渲对了，屏幕上什么都没有 | 地面必须是有底色的**面**。黑影子叠在近黑背景上没有可压暗的余地 |
| 正交 far 取满 `height` | 深度图整片是 1.0，影子消失 | far 留 1.4 倍余量，否则底面与「空」分不开 |
| 16 个固定螺旋采样 | 地面上出现等距环纹，像水波 | 逐像素抖动，把环纹换成噪点 |

顺带关掉了 `shadowMap`：地面改成 shader 之后，场景里没有一个 `receiveShadow` 的对象，
2048² 的阴影贴图每帧白渲。省下的是真实帧时间。

### 2. 光棚（借 `webgl_materials_*` 的打光思路）

金属之所以像金属，不是因为 `metalness = 1`，是因为**它反射的东西有结构**。

第一版 4 块接近正方形的面板 → 曲面高光糊成一团 → 读起来是灰塑料。
改成「宽顶棚 + 两条细长光管 + 地面反光板」之后，圆柱面上出现一条水平亮线——
人眼判「这是金属，而且是磨过的」，靠的就是这条线。

同时给材质表加了第四项 `envMapIntensity`。容易被漏掉，但它才是「这块金属有多亮」的开关：
只调 `metalness` 不调环境强度，深色阳极件会一直是死黑。

### 3. 正面补光

位置跟着相机走，强度 0.35。没有它，朝向观众的那一面永远是死黑——
而那一面恰好是观众唯一在看的面。强度必须低，高了就把体积压平，变成一张贴图。

### 4. 材质表扩充（6 → 9）

新增 `stainless` / `copper` / `pom_white`，并把原有六项按真实工艺重调：
阳极氧化 0.74/0.40（不是 0.62/0.36）、钢 0.98/0.18（不是 0.96/0.24）。

## 四、下一批候选（按投入产出排序）

这不是路线图，是**候选池**。进不进 P1，看它能不能回答「它帮谁确认了什么」。

| 优先级 | 能力 | 对应示例 | 为什么值 |
|---|---|---|---|
| **P0** | 环境光遮蔽（GTAO） | `postprocessing_gtao` | 孔内、台阶、法兰与壳体的缝隙变暗。**这是当前最缺的一口气**：接触阴影只管地面，管不了零件之间的缝 |
| **P0** | 剖切面封盖 | `webgl_clipping_stencil` | 现在剖开是空心壳，看到的是内壁的背面。封盖之后剖面才有「实体」的读法 |
| P1 | 程序化表面纹理 | `webgl_materials_*` | 拉丝、喷砂、磨砂。现在所有面都是纯色，凑近看是塑料 |
| P1 | 页内测量 | — | 点两点量距离，和标注数值对账。这是「能被反驳」的最后一步 |
| P2 | 阵列特征 instancing | `buffergeometry_instancing` | 24 个螺栓孔现在是 24 份几何。孔数上百时会掉帧 |
| P2 | 三视图联动 | — | 正交三视图 + 一个透视，四个相机同步。工程评审的真实工作方式 |
| P3 | glTF 导出 | `webgl_loader_gltf` | 确认件 → 建模起稿的交接。P3 阶段的事 |
| 不做 | 景深 / 泛光 / 故障风 | `postprocessing_*` | 装饰。答不上「它帮谁确认了什么」 |

**为什么 AO 是 P0 而不是「锦上添花」**：确认件的核心承诺是「这组数字自己不打自己」，
而人读一张图时，判断「这里有个台阶」靠的正是那条暗缝。没有 AO，
两个贴合的法兰看起来是一个整件——**尺寸线指着它们，人却看不出它们是两件**。

## 五、判定的依据

只有一句话：

> **每加一个效果，先问它帮谁确认了什么。答不上来的，就是装饰。**

这条规则会把 620 个 demo 砍到 10 个，也会把「加个音效吧」这种合理建议挡在门外。
挡的时候要给出理由，而不是「我们不做」——理由写在
[`../guide/06-EXPERIENCE.md`](../guide/06-EXPERIENCE.md)。

## 六、这份地图怎么维护

`tests/test_visual.py` 守的是结构（接触阴影在、光棚有细长灯、材质有环境强度），
**不守这份文档的数字**。数字会过时，结构不会。

three.js 每次大版本更新后，重跑一次抓取脚本、更新第一节的分布即可。
判定的结论（哪类取、哪类不取）不应该频繁变——如果变了，说明产品定位变了，
那是比这份文档更大的事。

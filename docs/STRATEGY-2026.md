# 从「生成」到「验收」

**visual-3d-forge 的赛道判断、算法地图与 12 个月路线**

> 版本 1.0 · 2026-11-18 · English: [`STRATEGY-2026_EN.md`](./STRATEGY-2026_EN.md)
> 这份文档回答的是"往哪走"，不是"怎么做"。所有结论都可以被证伪，但必须给出证伪的判据。

---

## 一、先否定一个定位

如果这个项目对外说"我用 AI 生成 3D 网页"，它就在一条必输的赛道上。

原因不是竞争激烈，而是**它的价值会随模型能力提升而衰减**：

| 年份 | 生成一段可运行的 three.js 场景 | 我们作为"胶水层"的价值 |
|---|---|---|
| 2023 | 需要人写两周 | 高 |
| 2025 | 一次对话，60 分水平 | 中 |
| 2027 | 一次对话，80 分水平 | 接近零 |

"生成"是一条**能力曲线**，模型每年都在往上爬。任何建立在"帮模型补最后 20 分"上的产品，都会在 18 个月内被吃掉。v0、Bolt、Lovable 已经证明了这一点：它们卖的是"更快地生成"，所以必须不停地追新模型。

**能活下来的位置，是模型不会自动变强的那些地方。**

---

## 二、护城河：四件模型不会自动做的事

这不是"愿景"，是这个项目**已经部分具备**、但还没做透的四件事。

### 1. 确定性（同输入 → 同产物）

大模型的输出是概率的。企业采购三维内容时，第一个问题不是"好不好看"，是**"上次那版还能不能重出"**。

`charter` 里的"确定性不变量"（11.2-V1）说的就是这个。要把它变成产品能力：

- 同一份 IR + 同一个 seed → 字节级一致的产物
- 版本升级时，旧 IR 仍能编译（向后兼容承诺）
- 差异可视化：v1 和 v2 的产物差在哪几个构件

> **判据**：给定同一个 IR，在三个不同机器、两个不同 three.js 版本上编译，产物哈希一致（允许渲染器版本差异导致的浮点噪声，需定义容差）。

### 2. 可验收（产物自带合格证明）

现在的 19 项契约校验是**结构级**的：文件存在、没有远程引用、材质数量一致、体积在预算内。

这只是"体检报告的第一页"。真正值钱的是**几何级**验收：

- 没有非流形边、没有自交面、法线朝向一致
- 装配无干涉（齿轮不会穿进齿圈壁）
- 尺度符合物理先验（车门高 1.1m 而不是 11m）
- 性能在预算内（三角面 < N、绘制调用 < M、目标帧率达成）

> **判据**：一份产物能生成一页 PDF/HTML 报告，任意第三方可以按报告复现验收结论。

### 3. 可续接（能被专业工具接过去继续做）

这是最容易被忽略、也最能建立壁垒的一条。

客户不会只要一个网页。他们要的是：网页给市场和销售用，模型给工业设计和影视用。

如果产物是"一堆没法导出的 three.js 代码"，它就死在浏览器里了。如果产物是"一份能导出 USD/glTF 的 IR"，它就进入了客户的生产管线——**从一次性交付变成基础设施**。

> **判据**：产物导出 glTF 后，在 Blender 里打开，层级、材质、尺度与网页内一致（误差 < 1%）。

### 4. 领域先验（知道"这个东西应该长什么样"）

模型知道"跑车有尾翼"，但不知道"这个级别的车轴距应该是 2.7m，轮距 1.6m，轮胎扁平比 30"。

先验是可以积累的资产：一旦建了汽车、家具、建筑构件、展陈道具的参数库，后来者要追就得重建一遍。

> **判据**：同一句意图，接入先验库前后的产物，在"比例失真"的人工评分上差距 > 1 个等级。

## 三、算法：按 ROI 排序的六项能力

不是"要做什么 AI"，是"要补哪些确定性算法"。**越靠前的越该自研，越靠后的越该用现成的。**

| # | 能力 | 现状 | 要补什么 | 来源 | ROI |
|---|---|---|---|---|---|
| 1 | **几何合法性** | 结构级 19 项 | 拓扑校验（非流形/自交/法线）、BVH 干涉检测、装配间隙 | `three-mesh-bvh` + `manifold-3d`，胶水自研 | ★★★★★ |
| 2 | **尺度先验** | 靠 LLM 猜 | 人体工学 / 建筑模数 / 车辆参数 / 材料工艺库 | **必须自建** | ★★★★★ |
| 3 | **感知校准** | 手调曝光 | 直方图目标约束的自动曝光、白平衡、对比度定标 | 自研（200 行内） | ★★★★☆ |
| 4 | **自动构图** | 手调机位 | 包围盒 + 视觉显著性 + 三分法/黄金分割约束求解 | 自研 | ★★★★☆ |
| 5 | **性能预算** | 固定质量档 | 三角面/绘制调用预算、按目标帧率自动 LOD、纹理尺寸决策 | 自研 | ★★★☆☆ |
| 6 | **语义反演** | 无 | 参考图 → 参数（尺寸/材质/结构） | 依赖 VLM，做后处理校准 | ★★★☆☆ |

### 为什么第 1 项是最高优先级

因为它是**"可交付"这三个字的物理基础**。

一份有自交面的模型，在网页里可能看不出来（背面剔除 + 光照掩盖），但一旦进 3D 打印、进 CNC、进游戏引擎的碰撞体，立刻崩。客户第一次踩坑，就再也不会信第二次。

而且这项能力**可以被测试**：造 200 个已知有缺陷的模型，看校验器召回率。这是可以写进合同的指标。

### 为什么第 2 项必须自建

因为它是唯一**无法从公开数据里学到**的东西——它是行业知识。

举例：一句"做一张办公桌"，模型会生成 0.75m 高（对的，这是标准桌高），但抽屉深度、腿部净空、走线孔位置，全靠猜。这些数字在 GB/T 3326 里写着，在木工师傅脑子里，不在训练数据里。

把它做成"先验库 + 约束检查"，就是产品。做成"提示词里多写几句"，就还是 demo。

### 一个反直觉的结论

**第 6 项（图 → 参数）看起来最像"AI"，其实最不该优先做。**

原因：它是四项里唯一**依赖外部模型能力**的。VLM 的图理解每年都在变强，今年做的反演管线，明年就被基座模型内置了。

正确的做法是：把反演做成**可替换的适配层**，今天接 VLM，明天接更强的 VLM，而后面的"参数 → IR → 产物"永远不变。

## 四、协同：与专业软件的三级接口

这一层决定了这个项目是"玩具"还是"管线里的一环"。

### L0 · 导出（1-2 周可完成）

| 格式 | 用途 | 难点 |
|---|---|---|
| **glTF / GLB** | 通用交换，Blender/Unity/Unreal 全支持 | PBR 材质映射、节点层级保持、Y-up/Z-up 转换 |
| **USDZ** | Apple 生态（AR Quick Look、Vision Pro） | 需要 USD 库，或走 `usd-core` Python |
| **PNG 序列 / WebM** | 市场物料，不需要 3D 能力 | 已有录制管线 |

**关键设计**：导出不是"再写一个导出器"，而是 **IR 本身就按 glTF 的数据模型设计**（节点树 + PBR 材质 + 变换矩阵）。这样导出是"序列化"，不是"翻译"。

### L1 · 交换（1-2 月）

| 格式 | 为什么值钱 |
|---|---|
| **USD**（.usda/.usdc） | 影视、工业设计、汽车的标准场景格式。能进 USD，就能进客户的主管线 |
| **OpenEXR 多层** | 渲染合成用，需要 AOV（景深/法线/ID 通道） |
| **材质库（.mtlx / MaterialX）** | 材质跨软件复用 |

USD 的关键是**层叠（Layer）**：base.usda 放几何，look.usda 放材质，shot.usda 放机位与动画。这正是 IR 该有的结构——现在 IR 是一个扁平对象，要拆成三层。

### L2 · 回写（3-6 月，双向）

这是真正的门槛：不只是"导出给你"，而是**"你在专业软件里改完，能回写进 IR"**。

| 目标 | 形态 | 价值 |
|---|---|---|
| **Blender** | `bpy` 脚本：读 IR → 建场景；读场景 → 写 IR | 中小团队最普及，脚本生态好 |
| **Houdini** | HDA（数字资产）：IR 作为参数接口 | 程序化生成的王者，天然契合 |
| **Unreal** | Datasmith / USD Stage | 实时渲染与虚拟制片 |
| **C4D** | Python 脚本 | 广告行业标准 |

**回写的技术前提**：IR 里每个构件必须有**稳定 ID**（不是数组下标），并且能被外部工具"认领"。否则 Blender 里改完导回来，系统不知道哪个是哪个。

> 这一条现在就要做：IR 加 `uid` 字段。改动很小，但不做的话，L2 阶段要重构。

## 五、商业：五个方向，一个顺序

先给结论：**从"品牌互动"切入，用"汽车配置器"立标杆，用"电商商品页"做规模。**

| 方向 | 客单价 | 壁垒 | 交付周期 | 进入顺序 |
|---|---|---|---|---|
| **品牌互动 H5** | 3-15 万/项目 | 低（但审美门槛高） | 2-4 周 | **① 先做** |
| **汽车/工业配置器** | 30-200 万 | **高**（几何+规格+性能） | 3-6 月 | ② 立标杆 |
| **电商商品 3D 页** | 500-5000/ SKU | 中（规模化难） | 天级 | ③ 做规模 |
| **建筑/室内可视化** | 5-50 万 | 中高（需 BIM 对接） | 1-3 月 | ④ 后置 |
| **教育/科普** | 低，但政策友好 | 低 | 长 | ⑤ 机会型 |

### 为什么先做品牌互动

1. **它正好是这个 demo 的形态**——NOVA X-01 就是一个"品牌互动页"：有车、有场景、有参数、有交互、有分享欲。
2. **验收标准是"好看"，不是"精确"**——这让我们现在的技术栈（渲染 + 运镜 + HUD）刚好够用。
3. **它产生案例**——案例是这一行唯一的销售材料。
4. **它容错**——做砸一个 H5 不会毁掉客户管线，做砸一个配置器会。

### 为什么第二个做配置器

因为它是**唯一能把四条护城河全部用上的品类**：

- 确定性：同一个 SKU 的配置页，今天和三个月后必须一模一样
- 可验收：车轮不能穿进轮拱，车门开启角度不能撞到后视镜
- 可续接：整车厂要把模型导进他们的 CATIA/VRED 管线
- 领域先验：轴距、轮距、离地间隙、配色工艺，全是有标准答案的

而且这个 demo 已经是雏形了：部件矩阵（拆解）、规格控制台（参数）、材质切换（配色）、测试场（性能展示）——**这就是一个配置器的四个核心界面**。

### 为什么电商商品页放第三

量大、单小、要求低，但它需要**规模化能力**（今天做 500 个 SKU），而规模化的前提是模板库 + 自动化验收。前面两步没做完就做这个，会变成人力外包。

## 六、关于"创意工坊"：我建议不做

你问的是"要不要统一化开发一个创意创新工坊"。

我的判断是：**不要做"工坊"这个产品形态。至少现在不要。**

### 理由一：工坊是"面板思维"，会滑向低代码红海

"工坊 / Studio / 工作台"的本质是：把能力摊开成按钮，让人来点。

一旦这么做，产品就要回答"这个按钮为什么不能点""这个参数为什么不生效""为什么我调了没反应"——**你在做一个编辑器，而编辑器的对手是 Blender、C4D、Spline，你赢不了。**

更糟的是：编辑器把用户变成"操作员"，而操作员永远会问"能不能再加个功能"，需求会无限膨胀，最后变成一个什么都不精的四不像。

### 理由二：工坊会让"确定性"这个优势消失

工坊的交互本质是**连续的、不可复现的**：拖一下、调一下、撤销、再拖。产物是"操作历史的终点"，不是"规格的编译结果"。

而我们的护城河第一条就是"同输入同产物"。工坊会亲手把它毁掉。

### 那应该做什么

**做"陈列馆 + 编译器"，不做"编辑器"。**

| 工坊（不做） | 陈列馆 + 编译器（做） |
|---|---|
| 用户拖拽搭场景 | 用户写一句话 / 给一张图 / 选一个规格 |
| 产物是一堆可调参数 | 产物是一个可运行的东西 + 一份验收报告 |
| 卖工具 | 卖确定性 |
| 需要保存"项目文件" | 需要保存"意图卡 + IR" |
| 用户是设计师 | 用户是**要交付的人**（市场、产品、工程） |

具体形态：

1. **Gallery（作品墙）**：每个作品点进去能玩、能改**有限参数**（颜色、场景、机位），改完直接出一份新的单文件 HTML。参数是白名单，不是无限自由度。
2. **Spec Editor（意图卡编辑器）**：不是画图，是填表——"我要一个汽车配置页，5 个场景，D2 档交付，目标 60fps"。这是**声明式**的，所以可复现。
3. **Report（验收报告）**：每次编译产出一页，写清楚"这份产物为什么合格"。这是给甲方看的，也是给内部做回归的。

> 一句话：**工坊让人操作，编译器对结果负责。我们卖的是后者。**

## 七、12 个月路线图

四个阶段，每个阶段都有一个**可证伪的验收判据**。做不到就不进入下一阶段。

### P0 · 0-8 周｜Demo 即标准

**目标**：把这次的 NOVA X-01 变成"旗舰样例"，并让 5 个 showcase 各自带一份验收报告。

- 5 个 showcase：展台 / 城市夜雨 / 山地 / 冰雪 / 直线加速（已具备场景，需固化）
- 每个 showcase 有：入口页、参数白名单、校验报告、录制好的动图
- 发布 v2.1，把"示例不公开源码"作为**产品策略**写进 README（交付物是产物，不是源码）

**判据**：一个没听过这个项目的人，打开 Gallery，30 秒内能说出"这东西能干什么"，并且愿意点开第二个作品。

### P1 · 2-4 月｜IR 2.0 + 双向导出

**目标**：IR 能被 USD / glTF 表达，能被 Blender 打开并回写。

- IR 拆分三层：`geometry` / `look` / `shot`（对应 USD 的 layer）
- 每个构件加稳定 `uid`
- glTF 导出（PBR 材质 + 节点层级 + 尺度 1:1）
- Blender `bpy` 双向脚本：`ir2blend.py` / `blend2ir.py`
- **不做**：USD 完整支持（先做最小子集：Xform / Mesh / Material）

**判据**：导出的 glTF 在 Blender 里打开，包围盒尺寸与网页内一致（误差 < 1%）；改一个材质颜色，回写后网页重编译能看见。

### P2 · 4-7 月｜从结构校验到几何校验

**目标**：验收报告从"文件级"升级到"几何级"。

- 拓扑校验：非流形边、自交面、法线一致性、退化三角形
- 干涉检测：装配体两两 BVH 求交（齿轮/轮拱/悬架）
- 尺度先验库 v1：车辆（轴距/轮距/离地间隙）、家具（桌高/坐高/柜深）、展陈（人眼高/通道宽）
- 感知校准：自动曝光（直方图 P95 目标）+ 自动构图（包围盒 + 三分法）

**判据**：造 200 个已知缺陷模型，召回率 > 85%，误报率 < 10%；自动曝光的产物与人工调优的产物，在盲测中无法被区分（> 50% 混淆）。

### P3 · 7-12 月｜垂直方案落地一个

**目标**：选一个方向（建议汽车配置器），做端到端案例，证明"进得了客户管线"。

- 输入：一份真实的车型规格表（PDF/Excel）
- 输出：配置页（5 场景）+ glTF（进 Blender）+ 验收报告
- 交付形态：单文件 HTML（离线可用）+ 资源包

**判据**：客户方的 3D 团队能在不修改我们代码的前提下，用他们自己的工具链继续编辑产物。

## 八、三个风险与对策

### 风险 1：模型能力吞噬"生成层"

**表现**：明年 Claude/GPT 直接输出 80 分的 three.js 场景，我们的生成模块变成累赘。

**对策**：把生成层做成**可替换的驱动**（`driver: "llm" | "template" | "manual"`），IR 与校验层不动。生成越强，我们越省事；生成不变强，我们也能靠模板活下去。

**不要做的事**：把核心竞争力押在"提示词工程"上。那是耗材。

### 风险 2：单文件交付被"在线编辑器"取代

**表现**：客户说"我为什么要一个 HTML 文件？我要能在线改"。

**对策**：单文件不是"技术限制"，是**交付承诺**——它能离线、能发邮件、能放进 U 盘、能十年后还能打开。这是**归档价值**，不是"简陋"。

要在文案上说清楚：**"给的不是一个链接，是一个文件。"**

### 风险 3：只做 demo，进不了生产

**表现**：作品很好看，但没人付钱，因为"我们的管线接不进去"。

**对策**：P1 阶段的 glTF/USD 导出，不是"锦上添花"，是**生死线**。宁可少做两个 showcase，也要把导出做扎实。

## 九、一页纸总结

| 问题 | 结论 |
|---|---|
| **赛道** | 不是"AI 生成 3D"，是"三维交付的确定性与可验收性" |
| **护城河** | 确定性 / 可验收 / 可续接 / 领域先验（四件模型不会自动变强的事） |
| **最该补的算法** | 几何合法性校验（不是生成） |
| **最该建的资产** | 尺度先验库（行业知识，无法从公开数据学到） |
| **最该做的接口** | glTF 导出（1-2 周）→ USD 层叠（1-2 月）→ Blender 回写（3-6 月） |
| **先做哪个商业方向** | 品牌互动 H5（快、能证明）→ 汽车配置器（深、能立标杆）→ 电商（规模） |

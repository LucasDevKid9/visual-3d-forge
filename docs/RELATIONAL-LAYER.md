### 0.2 分叉是怎么发生的

不是谁改错了，是**合并基线和后续演进没有对齐**，且缺一张映射表。

`INSTALL-MANIFEST.json` 自述合并基线是 `github-main-v2.7`（tree `776f10d`）。而 GitHub 之后继续走到 v2.8 / v2.9（交付形态四档、五脚本、依赖闸）。合并基线选了一个**正在移动的目标**，合并完成后也没有回摘上游增量。

编号重排本身是合理决策——`SKILL.md:349` 写明「20-25 号 references 与 7 个扩展脚本来自仓库，编号重排以避免与主体冲突」。问题不在于重排，在于**重排之后没有留下任何编号映射**：`09` 在两侧指向两个不同文件，且没有任何一处记载这件事。

这就是关系层缺失的最小样本：**做了一次位置变更，但没有声明这次变更对依赖它的 24 处引用意味着什么。**

### 0.3 为什么这比穿模更危险

两侧各自自洽，**单独用都不会出错**。危险出现在跨本体搬运的那一刻：把 GitHub 的某节正文挪进本地，或把本地的 references 推到远端——`references/11-threejs-r187-api.md` 会解析到 `11-r3f-patterns.md`。

文件存在、链接检查通过、内容是错的。**不 404 的错误比 404 更难查。**

这与你诊断的病症是同一个结构：

| 你的诊断 | 在 skill 自身的复现 |
|---|---|
| 位置只是孤立的绝对值 | 文件名编号是唯一坐标，重编号即全部失效 |
| 元素间依赖从未声明 | 24 处交叉引用靠硬编码前缀，没有稳定 ID |
| 改动一处，相关处不跟随 | SKILL.md 的算法地图改编号，24 个文件不跟随 |
| 算法全绿、现实不成立 | 所有链接检查通过（文件存在），语义全错（指向别的内容） |

**结论：关系层的第一条不是给几何用的，是给 skill 自己用的。** 在它被修好之前，任何对 SKILL.md 的增量修改都会制造第三份分叉。

## 1. 定性：一个统一判据

### 1.1 三类症状同源

| 症状 | 表面原因 | 共同原因 |
|---|---|---|
| 穿模 | 两个构件坐标撞在一起 | 该坐标没有来源，是手填的绝对值 |
| 悬空 | 构件下方没有承托件 | 该坐标没有来源，且「必须有承托」从未被声明 |
| 断裂 | 传动链中间少一段 | 端点坐标各写一份，中间段没有任何数据结构声明 |
| 装饰件 | 有视觉、无功能 | 该元素与任何状态量都没有绑定关系 |

四者的共同点不是「几何错了」，是**系统里存在大量无来源的绝对值，以及未被声明的二元关系**。

### 1.2 位置可溯源性（Position Provenance）

现有 schema 已经对**尺寸**做了溯源：

```yaml
evidence:
  dia: {value: 620, grade: measured, src: "图纸 A-102"}
```

`grade` 三档：`measured` / `inferred` / `standard`。但**位置没有对应的机制**。

判据：

> 每一个 transform 必须能回溯到四类来源之一，且回溯链终止于 `world` 帧：
> `constraint`（装配约束求解）· `measured`（图上有标注）· `standard`（公称/标准件）· `derived`（由其他量算出）。
> **终止不了的，就是孤立元素。**

现状核对——`scripts/spec_compile.py:234`：

```python
pos = {p["uid"]: [0.0, 0.0, 0.0] for p in parts}   # 所有件初始位置都是原点
```

无约束件永远停在原点，**不报错、不警告、不计数**。原点假装成一个位置：它让「孤立」看起来像「装配」。

**原点不是位置，是沉默。**

### 1.3 为什么加法式质量观必然漏

现有 18 条硬契约、15 条红线，主语全是单件：

- 「材质分裂」的主语是一块表面
- 「默认机位」的主语是一个相机
- 「无尺度感」的主语是整个画面

没有一条的主语是「A 与 B 之间」。缺陷因此落在规则集的**补集**里。

这不是规则写得不够多，是**语法表达不了二元关系**：红线都是 `P(x)`，缺陷都是 `Q(x, y)`。加长清单解决不了，必须扩展语法。

## 2. 内核（不可协商）

| # | 内核 | 判据（可机器检查） | 违反的后果 |
|---|---|---|---|
| **K1** | **关系先于元素** | 每个元素至少有 1 条关系声明（connect / clear / reach）；0 条即为孤立 | 元素堆在原点互穿，且无告警 |
| **K2** | **位置可溯源** | 每个 transform 有 `provenance`，回溯链终止于 `world` | 无法回答「这个坐标从哪来」 |
| **K3** | **双参照系可逆** | 一切位置写成 `frame + 局部值`；跨帧比较前必须 `toWorld()` | 「看起来对齐」而实际差 40 mm |
| **K4** | **非破坏重算** | 几何由参数 + 关系重算；禁止在生成结果上打补丁 | 改一处，其余静默漂移 |

K1–K5 与现有「不要先写代码，先建模型」同源：建模型 = 建关系。差别是**「模型」这个词太软，可以被理解成「在心里想一下」；「关系声明」是文件里的表格，想漏都不行。**

## 3. 五机制的迁移判定

只取机制，不搬功能——但「不搬」不等于「全搬过来改个名」。逐条判定：

| 你提的机制 | 3D 软件的真身 | 判定 | 迁移形态 |
|---|---|---|---|
| 坐标系（世界/局部） | `matrixWorld` 链 | **直接可用** | `frames` 树，`toWorld(frame, local)` 可逆 |
| 绑定与约束 | Parent / Constraint / Weight | **先修接线** | 现有 `assembly` 已声明 4 类约束，但 solver 只认 `mate`；`coax` 是**死声明**——被检查，却不参与求解 |
| 连续性（G1/G2） | NURBS 高阶连续 | **必须改写**（见 3.1） | 拆成「接口实现件」与「时间缓动」两个对象 |
| 渲染分层 | Scene graph / shader 分离 | **已有雏形，制度化即可** | 合批前留档 `solidBoxes`，审计读留档不读渲染对象 |
| 修改器栈 | Modifier stack | **不迁移，降级**（见 3.2） | 声明式重算 + 构建快照 diff |

### 3.1 曲率连续的正确迁移

曲率的本质是「接口处的高阶导不跳变」。直接搬到视觉层是比喻；搬到**装配接口**上是精确同构：

| 阶 | 装配含义 | 判据 | 缺失时的现象 |
|---|---|---|---|
| **C0** 位置相容 | 接触面重合，无缝无穿 | `mate` 间隙 ≤ 1 mm | 缝隙 / 穿模 |
| **C1** 切向相容 | 轴线、切平面一致 | 同轴度 ≤ `max(0.25, r×0.02)`；共面度 ≤ 0.5° | 「看着接上了」，一转就露馅 |
| **C2** 曲率相容 | 过渡件存在 | 截面积突变比 > 1.5 时必须有锥段/圆角/法兰 | 大管直连小管、直角硬拐 |

我上次做正交布管时加的弯头，就是 C2 的实现件。当时叫它「工程规范」，其实它就是 C2——**因为没有名字，所以它不能被审计，只能被记得**。

同一套三阶放到时间轴上：

| 阶 | 动效含义 | 判据 |
|---|---|---|
| 时间 C0 | 状态位置连续 | 无瞬移 |
| 时间 C1 | 速度连续 | 无硬切 |
| 时间 C2 | 加速度连续 | 无急刹 |

skill 已有「收束是减速不是急刹」（硬契约 17）——这正是时间 C2 的通俗写法。**给它阶数，它才能被检验；只给它形容词，它只能靠人记得。**

命名即约束。

### 3.2 为什么不迁移修改器栈

真做 modifier stack 需要：参数化重建管线（现有 `spec_compile.py` 是一次性编译，非 live rebuild）、每步的差分存储、与 `geometry.dispose()` 的生命周期对齐。

代价是复杂度上升；收益是「浏览器内可回滚」。但单文件交付的读者不会在页面里编辑几何——**收益方不在**。

正确的迁法是搬「非破坏」这个**性质**，不搬「栈」这个**形式**：

```
改 YAML → 重编译 → 新旧 IR diff → 差异报告
```

回滚靠 git，不靠运行时栈。这是一条异议：为了元规范破坏载体契约（硬契约 1：单文件、无构建工具）不划算。

## 4. 模块架构

### 4.1 模块表

| 模块 | 职责（单一） | 输入 | 输出 | 依赖 |
|---|---|---|---|---|
| **M0 Kernel** | 五条内核 | — | 全局约束 | — |
| **M1 Frame** | 参照系与可逆换算 | `units`、`frames` | `toWorld / toLocal` | M0 |
| **M2 Decl** | 元素与关系声明 | 构件树、装配意图 | `parts[]`、`relations[]` | M1 |
| **M3 Graph** | 依赖图与传动链 | `graph.nodes/edges` | 拓扑 + 连通性报告 | M2 |
| **M4 Resolve** | 约束求解与冲突裁决 | 声明 + 求解顺序 | 世界变换 + 冲突表 | M1,M2,M3 |
| **M5 Occupy** | 占位体与净空 | 元素几何 | OBB/胶囊集合 | M1 |
| **M6 Audit** | 六项审计 | M3/M4/M5 输出 | 三栏报告 | M3,M4,M5 |
| **M7 Present** | 表现层 | 几何 + 材质 | 渲染 | 只读 M4 |
| **M8 Rebuild** | 非破坏重算 | 参数变更 | 新 IR + diff | M4 |

关键约束：**M7 只读 M4 的输出，不得反写位置。** 一旦表现层能改位置，审计对象与渲染对象就分家了——这正是「截图验收」失效的根因。

### 4.2 依赖图

```
M0 Kernel

M1 Frame ──┬── M2 Decl ── M3 Graph ──┐
   │       │                          │
```

### 4.3 接口契约（待裁决）

在现有 `specsheet.schema.json` 上增量扩展三个顶层键，不破坏既有 `parts` / `assembly`：

```yaml
spec_version: "2"

frames:
  - {id: world,  parent: null}
  - {id: hull,   parent: world, origin: [0, 0, 0]}
  - {id: engine, parent: hull,  origin: [2.4, 0, 1.2], axis: x}

parts:
  - uid: flywheel
    kind: revolve
    label: 飞轮
    frame: engine
    evidence:
      dia: {value: 620, grade: measured, src: "图纸 A-102"}
    provenance:
      pos: {kind: constraint, from: "seat(flywheel, crank)"}   # 或 measured / standard / derived

assembly:
  - {type: seat,  a: flywheel, b: crank,       depth: 0.040}      # 坐入 40 mm
  - {type: coax,  a: flywheel, b: crank,       tol: 0.050}        # 同轴度 0.05
  - {type: clear, a: flywheel, b: bellhousing, min: 0.025}        # 净空 25 mm
  - {type: clear, a: flywheel, b: starter,     min: 0.010}
  - {type: reach, a: starter,  path: [300, 0, 0], dia: 120}       # 拆装通路

graph:
  nodes:
    - {id: pt-flange, frame: hull, p: [3.1, 0, 1.2], axis: x, r: 0.09}
    - {id: gear-in,   frame: hull, p: [2.4, 0, 1.2], axis: x, r: 0.11}
  edges:
    - {from: pt-flange, to: gear-in, kind: shaft, via: [gt-drop-shaft], minCover: 0.95}
    - {from: gear-in,   to: crank,   kind: gear,  ratio: 3.2}
  terminals:
    - {node: pt-flange, role: free}      # 自由端必须显式声明，否则视为遗漏
```

三条接口纪律：

1. `a` / `b` 必须存在且成对——现有 schema 只 `required: [type]`，允许悬空约束。
2. `clear` 的 `min` 无默认值，必须显式填写。默认值会让「没想清楚」伪装成「想清楚了」。
3. `graph.terminals` 必须与轴系数量一致。自由端不声明 = 链没画完。

## 5. 审计层

### 5.1 六项审计

格式：**谓词 → 阈值 → 失败后果**。阈值标 🔍 的需在真实项目上校准。

#### A1 依赖完整性（K1 / K2）

| 编号 | 谓词 | 阈值 | 失败 |
|---|---|---|---|
| A1.1 | 每个 `part` 至少被 1 条 relation 引用 | 0 条 → FAIL | 孤立元素 |
| A1.2 | 每条 relation 的 `a`/`b` 存在于 `parts` | 缺失 → FAIL | 悬空约束 |
| A1.3 | 约束图无环；求解 ≤ 40 轮收敛 | 超限 → FAIL | 环 |
| A1.4 | 每个 `part` 有 `provenance` 且链终止于 `world` | 终止不了 → FAIL | 无源坐标 |
| A1.5 | `graph.edges` 每条边的 `via` 实现件存在，几何沿边采样覆盖率 | ≥ 95% | 传动链空洞 |
| A1.6 | `terminals` 数量 = 轴系自由端数量 | 不等 → FAIL | 链没画完 |

#### A2 空间合法性（K1）

| 编号 | 谓词 | 阈值 | 失败 |
|---|---|---|---|
| A2.1 | 实体子网格级干涉，穿透深度 | > 2 mm → FAIL | 穿模 |
| A2.2 | 声明 `clear` 的关系，实测最小间距 | < `min × 0.9` → FAIL | 净空不足 |
| A2.3 | 任何实体超出 `bounds` | 越界 → FAIL | 出框 |
| A2.4 | 静止件最低点投到承托面 | ≤ 3 mm，或显式 `floating` + 支承件 | 悬空 |
| A2.5 | 转动件与静止件径向间隙 | ≥ `max(0.005, 0.02×r)` | 扫膛 |

必须用**子网格级 OBB**，不能用整件 AABB：合批会把整段管系压成一个巨型包围盒，「穿过」和「贴着走」无法区分。合批前留档 `solidBoxes`，让渲染粒度与审计精度解耦。

#### A3 接口连续性（K3 + C0/C1/C2）

| 编号 | 谓词 | 阈值 | 失败 |
|---|---|---|---|
| A3.1 | `mate` 实际间隙（C0） | ≤ 1 mm | 缝隙 |
| A3.2 | `coax` 横向偏移（C1） | ≤ `max(0.25, r×0.02)` mm | 偏心 |
| A3.3 | 截面积突变比（C2） | > 1.5 必须有过渡件 | 硬拐 |
| A3.4 | 相邻面材质参数差（视觉 C0） | 粗糙度差 > 0.15 且同材质 → WARN | 材质分裂 |

#### A4 现实可行性

| 编号 | 谓词 | 阈值 | 失败 |
|---|---|---|---|
| A4.1 | 旋转轴段跨距 | > 3 m 需中点支承 | 长跨无支承 |
| A4.2 | 需维护件的拆装通路 | 沿声明方向 300 mm 内无遮挡 | 拆不出来 |
| A4.3 | 承载件到基础的路由连通 | 图连通 | 力流断 |
| A4.4 | 装配序列存在拓扑排序 | 存在 | 互锁无法装配 |

A4 是唯一无法全自动的一项，但**可以自动生成待人工裁决的清单**——「以下 7 处需要你回答：现实中能否这样做」。这比「看起来没问题」强，因为它把问题变成可回答的。

#### A5 感知安全（三条底线）

| 编号 | 谓词 | 阈值 | 依据 |
|---|---|---|---|
| A5.1 | 正文对比度 | ≥ 4.5:1（大字 ≥ 3:1） | WCAG 2.2 AA |
| A5.2 | 闪烁频率 | ≤ 3 次/秒，且闪烁面积 < 25% 屏 | WCAG 2.3.1 |
| A5.3 | 单帧亮度突变 | > 20% → WARN | 光敏风险 🔍 |
| A5.4 | 同屏同时运动元素数 | > 12 → WARN | 认知负荷 🔍 |
| A5.5 | 无手势自动镜头角速度 | > 15°/s → WARN | 晕动 🔍 |
| A5.6 | `prefers-reduced-motion` | 必须响应，且降级后功能不减 | OS 级无障碍 |

A5.6 是新增：降级不能把功能也降掉，否则等于「为了不晕，别看了」。

#### A6 交互真实性

| 编号 | 谓词 | 阈值 | 失败 |
|---|---|---|---|
| A6.1 | 每个可点元素有 handler 且产生可观测状态变化 | 100% | 装饰件 |
| A6.2 | 每个持续动画绑定一个真实量 | 100% | 空转动效 |
| A6.3 | `cursor:pointer` 必有响应 | 100% | 假可点 |
| A6.4 | 每个状态可回退到初始 | 100% | 死路 |

A6.1/A6.2 可机器判定：挂 `pointerdown` 时断言状态对象发生 diff；rAF 内读写的量必须在 `state` 里存在对应键。

### 5.2 三栏报告

```json
{
  "algorithm":  {"pass": true,  "checks": 42, "fail": 0},
  "reality":    {"pass": false, "fail": 2, "items": [
    {"id": "A4.1", "what": "gt-drop-shaft 跨距 4.2 m 无中点支承"},
    {"id": "A2.2", "what": "flywheel 对 starter 净空 7 mm < 声明 10 mm"}
  ]},
  "perception": {"pass": true,  "fail": 0},
  "verdict": "BLOCK"
}
```

**为什么是三栏而不是两栏**：你第四节定了三层验收（交互/现实/视觉），第五节把审计压成两栏（算法/现实）。这两处不一致。

视觉三底线不属于「现实工程规范」——现实工程不管频闪；也不属于「算法」——算法全绿照样可以有频闪。压成两栏，第三层就没有出口，只能退化成「人工看一眼」——正是要消灭的那个形容词。

### 5.3 双闸，而不是末端一闸

你要求「在交付流程末端增设强制审计」。我主张拆成两道：

| 闸 | 位置 | 查什么 | 成本 |
|---|---|---|---|
| **前置闸** | P1/P2 之间（声明完成，代码未写） | A1 全部、A3.3、A4.4 | 改一行 YAML |
| **末端闸** | P5 交付前 | A2、A3.1–A3.2、A5、A6 | 重建几何 |

理由：修复成本 ≈ 从「产生位置」到「发现位置」的距离。

我上次那三处穿模，是在写几何代码时手填坐标产生的。如果 P1 阶段就要求「每条 `clear` 必须给 `min`」，写代码时就必须先查——穿模根本不会发生。

> 审计的价值不在于「发现错误」，在于**让错误无法被写下**。

### 5.4 豁免表

现实中必然存在合法重叠：轴穿轴承、叶根坐入桨毂、焊接搭接。纯算法会产生大量误报，误报的终点是「把阈值调大」——自欺。

要求：

1. 逐条登记 `{a, b, reason}`，双向匹配；
2. `reason` 必须是工程语言，不接受「设计如此」；
3. 文档由源码数组生成，CI 执行 `git diff --exit-code` 校验同步；
4. **豁免只能作用于 A2.1 / A2.2；A1 拓扑完整性、A3 连续性、A1.5 链覆盖不可豁免。**

第 4 条是防线：一旦允许豁免拓扑，豁免表就变成了缺陷收容所。

## 7. 我不认同的五条

| # | 你的原话 | 我的异议 | 替代 |
|---|---|---|---|
| 1 | 「在交付流程末端增设强制审计模块」 | 末端只能发现，不能防止；发现位置离产生位置最远，修复成本最高 | 双闸：P1 声明期 + P5 交付期 |
| 2 | 「审计结论分两栏：算法是否通过、现实是否通过」 | 与你自己第四节的三层验收不一致；视觉三底线两栏都装不下 | 三栏：算法 / 现实 / 感知 |
| 3 | 「非破坏性修改器栈：可叠加、可回滚」 | 在单文件、无构建工具的载体契约下，真栈的代价（复杂度）大于收益（收益方不存在——没人会在交付页里编辑几何） | 声明式重算 + IR diff，回滚靠 git |
| 4 | 「曲率连续决定曲面平滑 → 视觉与交互的过渡也须有连续性标准」 | 直接搬到视觉层是比喻，无法检验 | 拆成装配 C0/C1/C2（决定过渡件存在性）与时间 C0/C1/C2（决定跳变/硬切/急刹） |
| 5 | 「复杂度必须与任务量级相称」 | 只约束了上限，没约束下限。实际更常见的是**用极简掩盖功能缺失** | 补对偶：功能下限由任务类型决定，不得以降复杂度为由削减功能 |

第 5 条值得展开：skill 已有「体验外衣」红线（加个加载动画就叫沉浸式），但没有量化的下限。结果是「做得少」永远不会被判错，「做得多」反而处处受约束。**单向约束会系统性奖励偷工。**

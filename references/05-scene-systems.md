# 05 场景系统

目的：把「一堆部件」组织成一个可信的世界。几何对、材质对，场景系统错了照样不像。

## 世界尺度与坐标约定

三条约定，写进每个项目：

1. **1 单位 = 1 米**（three.js 默认光照与阴影参数为此调好）。
2. **Y 轴向上**，物体底部落在 `y=0`。
3. **原点在物体包围盒中心的地面投影处**，方便轨道控制围绕。

```js
// 归一化导入模型：任何 glb 都先做这一步
const box = new THREE.Box3().setFromObject(model);
const size = box.getSize(new THREE.Vector3());
const scale = 1 / Math.max(size.x, size.y, size.z); // 先归一到 ~1
model.scale.setScalar(scale);
box.setFromObject(model);
model.position.y -= box.min.y;  // 落到地面
```

**尺度锚**：画面里必须有一个已知尺寸参照（人形剪影 1.7m、A4 板、标尺刻度）。没有锚，观者读不出物体多大，再精细也白做。

## 相机：从尺度推导，不填固定值

```js
const R = bounds.getBoundingSphere(new THREE.Sphere()).radius; // 主体半径
const fov = 32;                        // 32–45°：稳重、形体感；不默认 75
const dist = R * 2.6 / Math.sin((fov * Math.PI / 180) / 2); // 由半径反解距离
camera.position.copy(dir.normalize().multiplyScalar(dist));
```

| 焦距(fov) | 观感 | 用在 |
| --- | --- | --- |
| 24–32° | 压缩、庄重、产品大片 | 产品主视图 |
| 35–45° | 自然、接近人眼 | 默认 |
| 50–60° | 略有张力 | 场景、建筑 |
| 70°+ | 强透视、游戏感 | 除非要夸张，不用 |

**构图先定主体占比**：主体占画面高度 55–70% 最稳；留白留在视线方向的一侧。

**正交投影**只在等距/工程/示意图时用——它抹掉深度线索，不适合产品质感。

## 光照关系：先定关系，再定亮度

三光制的职责：

| 光 | 职责 | 典型设置 |
| --- | --- | --- |
| 主光 Key | 定形体与投影方向 | DirectionalLight，强度 1.5–2.5，45° 侧上方 |
| 补光 Fill | 让暗部仍能读出结构 | HemisphereLight 或弱 DirectionalLight，强度 0.2–0.5，主光对侧 |
| 轮廓光 Rim | 把主体从背景剥离 | DirectionalLight 背对相机，强度 1–2，冷色或暖色偏离主光 |

```js
// 关键：三盏灯强度有明确比例，不要靠感觉加灯
key.intensity = 2.2; fill.intensity = 0.35; rim.intensity = 1.4;
```

**关系铁律**：
- 亮度属于同一个世界。暗部不够亮 → 调补光与环境，不要在多点随手加灯（会互相补偿，最后高光过曝、暗部浑浊）。
- 直射光决定形体，天空/环境决定暗部可读性，两者是独立的决定，不能并成一个亮度旋钮。
- 环境光（IBL）是可信度来源，不是可选项。

## 背景与地面

| 选择 | 用途 | 注意 |
| --- | --- | --- |
| 渐变纯色 | 产品展示 | 用径向渐变而非纯色，给一点点空间感 |
| studio 无缝背景（灰白） | 电商、目录 | 地面与背景同色，靠接触阴影区分 |
| 纯黑 + 镜面地 | 轻奢/科技 | 反光要压住，否则像广告模板 |
| 环境场景（桌面/车间） | 叙事 | 必须有尺度锚与合理光向 |

地面不能只是一张无限平面——要么给接触阴影，要么给微弱反射，否则物体浮空。

## HUD 与信息层

3D 之上永远需要一个 2D 层：

- 标题/副标题（说明这是什么）
- 图例（颜色/尺寸/工序的含义）
- 操作提示（拖拽旋转、滚轮缩放）
- 尺度标（可选但强烈建议）
- 步骤条（分步动画时）

原则：**3D 负责形体，2D 负责解释**。不要把大段说明塞进 3D 空间（除非做真正的空间标注）。

## 时间轴与状态

```js
const clock = new THREE.Clock();
let elapsed = 0;

function tick() {
  const dt = Math.min(clock.getDelta(), 1 / 30); // 防止切回标签页时大跳
  elapsed += dt;
  update(dt, elapsed);
  renderer.render(scene, camera);
}
```

**必须有**：暂停/继续、重播、单步（分步动画）、切后台暂停。
**不要有**：常驻匀速自转（除非用户明确要「转一圈看背面」的检视模式，且带暂停）。

## 后处理（按需）

| 效果 | 什么时候值得 | 成本 |
| --- | --- | --- |
| Bloom | 发光/霓虹/能量体为核心时 | 中 |
| SSAO/GTAO | 多物体、缝隙多、需要接触感 | 中高 |
| DOF | 摄影感、主视觉 | 高 |
| SMAA/TAA | 移动端锯齿明显 | 中 |
| 调色 LUT | 统一影调 | 低 |

**铁律**：一旦接后处理，色彩管理交给链末输出 pass，渲染器那侧关掉 toneMapping/outputColorSpace，否则双重转换导致发灰。

## WebGPU / TSL（可选进阶）

若用户明确要 WebGPU 或需要大量节点材质：
- 用 `WebGPURenderer`，但**必须**保留 WebGL 回退（`if (!navigator.gpu) { ... }`）。
- 节点材质（TSL）在 WebGL 后端也能跑，但 API 不同，不要混用 `MeshStandardMaterial` 和 `NodeMaterial` 的假设。
- 网页交付默认仍用 WebGL 路径：兼容性最好，且大多数需求不需要 WebGPU 的算力。

## 场景系统自检（P5 用）

1. 主体是否落地、有接触阴影？
2. 三光是否都有、强度有比例？
3. 机位是否由包围球推导、有极角与距离限位？
4. 是否有尺度锚？
5. 背景是否解释了主体（而不是抢主体）？
6. 是否有 2D 信息层？
7. 暂停/重播/切后台是否成立？
8. 色彩是否只转换一次（白是不是白）？

# 08 验收与交付

目的：用清单反证自己，把「我觉得不错」变成「逐项可核验」。

## 12 项验收清单（逐项打勾，不打勾不交付）

| # | 项 | 判定方法 | 常见不合格 |
| --- | --- | --- | --- |
| 1 | **打开即用** | 断网测试（CDN 缓存除外）或确认依赖可用；文件双击可开 | 依赖外部 .js / 需要起服务 |
| 2 | **形体可辨** | 从 3 个角度截图，剪影都能认出是什么 | 只有正面能看 |
| 3 | **比例正确** | 尺寸表与实际几何一致；最长/最薄比 > 20:1 | 部件比例失真 |
| 4 | **落地成立** | 物体与地面有接触阴影，不浮空 | 悬空、地面无反 |
| 5 | **光照关系** | 三光都有且强度有比例；无单光源死平 | 只有一盏平行光 |
| 6 | **材质一致** | 五通道描述同一块表面；无金属度当滑杆 | 全场景一材质 |
| 7 | **色彩正确** | 白是白、灰是灰；不发灰发黄 | 双重色彩转换 |
| 8 | **相机合规** | 机位由包围球推导；有极角/距离限位；fov≠75 | 能穿模/能转到空壳 |
| 9 | **交互可用** | 拖拽/缩放/点击有响应；触摸端可用 | 移动端不能操作 |
| 10 | **性能达标** | 桌面 ≥50fps、移动 ≥28fps；有降级机制 | 掉帧、发烫 |
| 11 | **兜底存在** | 无 WebGL 时有静态图 + 说明 | 白屏 |
| 12 | **信息层完整** | 标题、操作提示、图例、尺度锚（按需） | 只有物体没有解释 |

额外（工业/流程类必查）：
- 13 节拍/瓶颈有标注，不是纯动画
- 14 流程方向可读（箭头/流向）
- 15 尺度锚（人/标尺）存在

## 静态自检脚本

```bash
python3 scripts/validate_scene.py <你的页面.html>
```

检查项：单文件自包含、importmap 版本固定、CDN 黑名单、像素比封顶、色彩管理唯一性、resize、visibilitychange、相机限位、无 WebGL 兜底、fov 默认值、面数风险提示、材质分裂风险提示。
退出码非 0 必须修复后重跑，不能通过就说明契约没守。

## 人工验证（脚本查不出的）

1. **肉眼三角度**：正面、45°、背面（或背面如实留白）。
2. **移动端真机或缩窗到 390px**：UI 不重叠、能操作。
3. **断开网络**：确认静态资源都在本地或 importmap 命中缓存；不通过则改为本地 build 引入。
4. **放置 20 秒**：观察是否有匀速自转/粒子漂移在偷电。
5. **切到别的标签页 30 秒再回来**：不卡顿、状态正常。
6. **把窗口拉到很窄再拉宽**：画面不变形、相机构图仍成立。

## 交付话术模板

交付说明必须诚实、具体、可核验：

```
已完成：<文件名>.html

【基于什么做的】参考等级 R2（3 张不同角度照片），比例由 A4 纸标定（1px = 1.2mm）。
【推断了什么】背面走线按对称性补；内部腔体按进出料口功能链补；材质参数由照片高光形态反推。
【舍弃了什么】铭牌文字、内部螺丝细节、背景环境（不影响结构理解）。
【精度与性能】L1 档，约 12k 面 / 46 绘制调用；桌面 60fps，移动端自动降像素比。
【没做的】未做真实公差与工程尺寸；未做导出 glTF。
```

禁止的表述：
- 「完美还原」「1:1 复刻」「精确到毫米」（R3 以下不成立）
- 「支持所有设备」（没实测就不能说）
- 「完整实现了你的需求」（若有舍弃，必须列出）

## 常见打回原因（自查优先）

1. 用户要「看懂流程」，你交了一个漂亮的旋转模型 → 补信息层。
2. 用户要「真实感」，你只调了颜色 → 补 IBL 与接触阴影。
3. 用户说「能转就行」，你做了整段自动镜头 → 反而干扰。
4. 移动端打开是黑屏 → 缺 WebGL 兜底或用了 `transmission`。
5. 白色发灰 → 双重色彩转换。
6. 文件 8MB 全是贴图 → 改程序化或降分辨率。

## 交付后的迭代纪律

- 小改动（文案、配色、时长、镜头微调）直接改原文件，不重做。
- 结构性改动（换对象、换剧本、换精度档）回到 P1 重做构件树，不在旧代码上打补丁。
- 用户提出「不够真实/不够高级」时，先判断是**光**的问题还是**材质**的问题，不要同时改两样——改两样就不知道哪样起了作用。

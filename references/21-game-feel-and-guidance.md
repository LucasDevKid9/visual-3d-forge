# 21 · 游戏感与引导（Game Feel & Guidance）

> **适用于体验型与可玩产物。**
> 确认件只取本文的「引导三层次」——它正好对应 SpecSheet 里 `intent.audience` 的三档（外行 / 有基础 / 专业）。
> 动词设计、失败宽容、成就系统不适用。

> 用户不是"看网站"，是"在操作一个东西"。本文件解决：**怎么让操作有手感、有进度、有成就感，且不烦人。**

---

## 一、动词优先：先定动词，再定界面

样本 B 的十幕，每幕一个动词且不重复：**输入 → 观察 → 拍打 → 进入 → 行走 → 阅读 → 按住 → 敲击 → 选择 → 破坏**。

这不是文案，是**交互设计的第一性决策**。

### 动词清单与实现成本

| 动词 | 输入方式 | 实现要点 | 手感关键 |
|---|---|---|---|
| 看 Look | 鼠标移动 / 陀螺仪 | 视差、景深 | 延迟 ≤ 1 帧 |
| 转 Turn | 拖拽 | 惯性阻尼 | 松手后有 0.3s 余速 |
| 点 Tap | click / tap | 射线拾取 | 命中判定要"宽容"（扩大碰撞体 20%） |
| 拖 Drag | pointerdown + move | 平面投影 | 拖动体要"粘"在指针上 |
| 按 Hold | 持续按住 | 蓄力条 + 阈值 | 阈值前有"预热"反馈 |
| 敲 Knock | 快速连击 | 频率检测 | 每次敲击必须有独立音效 |
| 划 Swipe | 手势方向 | 速度阈值 | 方向判定用位移而非末速 |
| 摇 Shake | 设备加速度 | 阈值 + 冷却 | 冷却 ≥ 600ms 防连触 |
| 组合 Combine | 多选 + 确认 | 状态机 + 预览 | 预览要即时，不要等确认 |

**规则**：一个体验里 **动词种类 ≤ 5**。超过 5 种，用户记不住，且实现质量必然下降。

## 二、引导的三层次：默认不教

### 层次 1：不教（Self-evident）

适用于**通用隐喻**：
- 3D 物体可以转 → 用户默认会拖
- 有按钮样子的东西可以点
- 有滚动条的页面可以滚

**判断标准**：目标用户群体中 ≥ 90% 会自发尝试 → 不教。

### 层次 2：轻教（Affordance）

**不加文字**，用视觉暗示：

| 手法 | 例子 |
|---|---|
| 呼吸动画 | 可点物轻微缩放 1.0 ↔ 1.03，周期 2s |
| 光标变化 | `cursor: grab` / `pointer` / 自定义图标 |
| 幽灵演示 | 半透明的手/箭头做一次示范动作后消失 |
| 边缘微光 | 可拖物的边缘有一道流动光 |
| 静止中的微动 | 场景里唯一会动的东西就是可交互的 |

样本 B 用 `hints` 层 + `bt__cursor`（自定义光标）做轻教。

### 层次 3：重教（Explicit）

**必须给文字**，仅在以下情况：

- 动作是**非通用**的（摇手机、吹麦克风、多指手势）
- 动作**不可逆**（删除、提交）
- 动作是**核心卖点**且用户可能错过

重教的三要素：
```
一个动词（≤4 字） + 一个位置指示 + 一次可跳过的示范
```

样本 A 的 `Ring my bell to start` —— 7 个词，动词明确（ring），对象明确（bell），结果明确（start）。

### 引导的黄金 3 秒

进入体验后 **3 秒内**必须让用户完成第一次成功交互。
做不到 = 用户会离开。

**手段**：把第一个动词设计成"随便碰一下就行"（点任意处 / 移动鼠标 / 滚动一格）。

## 三、失败宽容：让用户永远不卡住

### 四条原则

1. **命中判定宽容**：碰撞体比视觉大 15–25%
2. **时间窗口宽容**：QTE / 节奏判定给 ±120ms 的"Good"区间
3. **自动纠错**：拖拽到接近目标位置时吸附（snap 半径 = 目标尺寸 × 0.15）
4. **无死路**：任何状态都能退出，且退出不丢进度

### 判定分级（样本 C 的 `--judge-*` 同款）

```js
function judge(dt, target, windows = { perfect: 0.05, great: 0.12, good: 0.22 }) {
  const d = Math.abs(dt - target);
  if (d <= windows.perfect) return { tier: 'PERFECT', score: 100, shake: 0 };
  if (d <= windows.great)   return { tier: 'GREAT',   score: 70,  shake: 1 };
  if (d <= windows.good)    return { tier: 'GOOD',    score: 40,  shake: 2 };
  return { tier: 'MISS', score: 0, shake: 4 };
}
```

**关键**：`MISS` 不能导致"重来"。只扣分，不阻断。阻断 = 挫败。

### 连击的正反馈

```js
combo++;
const mult = 1 + Math.min(combo, 10) * 0.1;   // 最高 2x
if (combo > 0 && combo % 5 === 0) {
  // 每 5 连给一次"升级"反馈：音效升调 + 数字弹跳 + 短暂描边发光
  confirm(523.25 * Math.pow(2, combo / 20));
  pulseScoreHUD();
}
```

连击的价值不是分数，是**让用户感到"我在变强"**。

## 四、进度与成就：让努力被看见

### 三种进度表达

| 类型 | 实现 | 适用 |
|---|---|---|
| **章节进度** | 底部 N 个点 / 顶部细线 | 线性叙事 |
| **能力进度** | 已解锁动词 / 已探索区域 | 探索型 |
| **分数进度** | 数字 + 星级 | 可玩型 |

样本 C 三者都有：`arcade-scoreboard-in`（分数）、`arcade-rank-in`（排名）、`arcade-player-stars`（星级）、`sequence7-training-progress`（训练进度）。

### 成就的三档设计

```
参与奖（必得）：完成即给，用于确认"你做到了"
表现奖（努力可得）：需要一点技巧，用于制造"我比别人强"
隐藏奖（偶然得）：需要发现，用于制造"我要告诉别人"
```

**规则**：参与奖 100% 可得，表现奖 30–50% 可得，隐藏奖 ≤ 10% 可得。

### 结算页的三件事

1. **一个数字**（分数 / 时长 / 完成度）
2. **一个称号**（"玻璃破坏者" / "八世界旅人"）
3. **一个动作**（重玩 / 分享 / 看下一件）

样本 C 的 `arcade-player-result` + `is-current-player` 就是这个结构。

## 五、可跳过：不是妥协，是尊重

### 三种跳过

| 类型 | 位置 | 实现 |
|---|---|---|
| **跳过引导** | ONBOARDING | 右上角 `SKIP`，3 秒后出现（太早出现显得不自信） |
| **跳过动画** | 任意转场 | 点击任意处立即完成当前转场 |
| **跳过整段** | JOURNEY | 章节导航，允许跳到任意幕 |

**样本 B 的反例值得学习**：它**不允许跳章**（十幕必须依次通关），但每一幕时长很短（平均 4.5s），所以不构成绑架。

**判断标准**：
- 单幕 ≤ 8s → 可以不給跳章
- 单幕 > 8s → 必须给跳章
- 总时长 > 90s → 必须给跳章

### 跳过的实现（不要硬切）

```js
function skipTransition() {
  // 不是 cancel，是"加速到终点"
  tweens.forEach(t => t.timeScale(8));
  setTimeout(() => { tweens.forEach(t => t.timeScale(1)); }, 120);
}
```

硬切会让用户失去空间连续性，加速则保留。

## 六、移动端：横竖屏是一等公民

样本 B 有 `Turn your phone sideways for a bigger picture`，样本 C 有 `mobile-orientation-guard`。

### 三种策略

| 策略 | 做法 | 适用 |
|---|---|---|
| **守卫** Guard | 竖屏时显示"请横屏"遮罩 | 强横向构图（宽幅场景、横向时间轴） |
| **自适应** Adapt | 重排 UI，相机 aspect 自适应 | 大多数情况 |
| **双版** Dual | 横竖各一套构图 | 成本高，仅旗舰项目 |

**推荐**：默认自适应，只在"横向构图不可妥协"时用守卫。

### 自适应检查清单

- [ ] `camera.aspect` 在 resize 时更新
- [ ] UI 用 `clamp()` 而非固定 px
- [ ] 触控目标 ≥ 44×44 CSS px
- [ ] 断点按**宽高比**而非仅宽度（样本 B 用 `max-aspect-ratio: 1/1`）
- [ ] 横屏矮屏（`max-height: 560px`）单独处理
- [ ] 双击缩放禁用（`touch-action: manipulation`）
- [ ] 安全区适配（`env(safe-area-inset-*)`）

### 触控与鼠标的差异

```css
@media (hover: hover) and (pointer: fine) {
  /* 悬停态只给有精确指针的设备 */
  .card:hover { transform: scale(1.02); }
}
```

**禁止**：把 hover 效果当主要反馈。触屏没有 hover。

## 七、街机化叙事：可迁移的五个机制

样本 C 把作品集做成了街机。这五个机制可以搬到任何领域：

| 机制 | 原始形态 | 可迁移到 |
|---|---|---|
| **玩家身份** | 输入名字，进排行榜 | 企业站：访客角色选择（采购 / 工程师 / 学生） |
| **关卡化** | 每件作品是一个 gauntlet | 产品站：每个功能是一个挑战 |
| **判定与连击** | QTE + Perfect/Great | 数据叙事：答对/答错，连对解锁 |
| **训练关** | sequence7 是 tutorial | 教程：先练后考 |
| **排行榜** | HIGH SCORES | 任何有可比性的场景（配置对比、方案评分） |

**注意**：游戏化不是加分数。游戏化的本质是**把"浏览"变成"完成"**。
如果加了分数但用户不知道"完成什么"，就是噪音。

## 八、手感调优：五个数值

| 参数 | 推荐值 | 作用 |
|---|---|---|
| 拖拽阻尼 | `0.88`（每帧乘） | 越小越"重" |
| 松手余速 | `0.92` 衰减 | 越大滑得越远 |
| 点击回弹 | `0.96 → 1.0`，120ms | 凹陷感 |
| 悬停缩放 | `1.02`，180ms | 存在感 |
| 相机跟随延迟 | `0.08`（lerp 系数） | 越小越"黏" |

```js
// 标准阻尼跟随
obj.position.lerp(target, 1 - Math.pow(0.001, dt));  // 帧率无关
```

**帧率无关**是硬要求：用 `1 - Math.pow(k, dt)` 而不是固定 `0.1`。否则 120Hz 屏上会快一倍。

## 九、自检清单

- [ ] 动词种类 ≤ 5，且相邻幕动词不同
- [ ] 3 秒内能完成第一次成功交互
- [ ] 非通用动作有文字引导
- [ ] 命中判定比视觉大 15–25%
- [ ] MISS 不阻断流程
- [ ] 有连击/累积的正反馈
- [ ] 结算页有数字 + 称号 + 下一步动作
- [ ] 单幕 > 8s 或总长 > 90s 时有跳过
- [ ] 触屏无 hover 依赖
- [ ] 触控目标 ≥ 44px
- [ ] 阻尼用帧率无关写法
- [ ] 全流程无死路（任何状态可退出）

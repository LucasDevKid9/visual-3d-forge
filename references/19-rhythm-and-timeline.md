# 19 · 节奏与时间轴（Rhythm & Timeline）

> **适用于体验型与混合型产物。**
> 确认件只取本文的「BPM 栅格」与「命名缓动」两节——时长吸附与曲线同源对任何产物都成立，转场类型学与镜头语法属于叙事，不适用。

> 节奏不是"感觉快慢"，是**可量化的时间栅格**。本文件给公式、给表、给代码。

---

## 一、BPM 栅格：把所有时长对齐到同一个拍

### 基本换算

```
beat   = 60 / BPM
bar    = beat × 4        (4/4 拍)
phrase = bar × 4         (4 小节乐句)
```

常用档位：

| BPM | beat | bar | phrase | 气质 |
|---|---|---|---|---|
| 90 | 0.667 | 2.667 | 10.67 | 从容、叙事、纪录片 |
| 110 | 0.545 | 2.182 | 8.73 | 稳健、企业、产品 |
| 128 | 0.469 | 1.875 | 7.50 | 推进、科技、EDM |
| **140** | 0.429 | 1.714 | 6.86 | 明快、游戏 |
| **174** | **0.345** | **1.379** | **5.517** | 高速、肾上腺素（样本 B） |
| 200 | 0.300 | 1.200 | 4.80 | 极限、短促、街机 |

### 时长量化函数

```js
function grid(bpm) {
  const beat = 60 / bpm;
  return {
    beat, bar: beat * 4, phrase: beat * 16,
    // 就近吸附到 1/2 拍栅格
    snap: (s, sub = 2) => Math.round(s / (beat / sub)) * (beat / sub)
  };
}
```

**用法**：所有转场、镜头位移、材质过渡的 `duration` 都过一遍 `snap()`。
不必严格等于，但误差应 ≤ 1/4 拍，否则观感"散"。

### 总时长反推

给定 BPM 和幕数，反推每幕时长：

```
单幕平均 = 总目标 / 幕数
幕时长 = snap(单幕平均) 取最近的小节整数倍
```

样本 B 校验：`49.66s ÷ 1.3793 = 36.0 小节` —— 整数，说明是**先定 BPM 和总长，再排幕**。

## 二、张力曲线：体验必须有形状

### 五型曲线

```
① 单峰（产品发布）        ② 双峰（品牌体验）        ③ 阶梯（教程/数据）
    ╱╲                      ╱╲    ╱╲                  ╱
   ╱  ╲                    ╱  ╲  ╱  ╲              ╱╱
  ╱    ╲                  ╱    ╲╱    ╲          ╱╱
 ╱      ╲___             ╱            ╲___     ╱╱______

④ 衰减（氛围/纪念）      ⑤ 循环（可玩/街机）
 ╲                        ╱╲    ╱╲    ╱╲
  ╲                      ╱  ╲  ╱  ╲  ╱  ╲
   ╲___                 ╱    ╲╱    ╲╱    ╲
```

### 选型

| 目标 | 曲线 | 理由 |
|---|---|---|
| 卖一个产品 | ① 单峰 | 一个记忆点就够，多了稀释 |
| 立一个品牌 | ② 双峰 | 第一峰抓人，第二峰留印象 |
| 讲清一件事 | ③ 阶梯 | 每阶一个结论，累积信任 |
| 缅怀 / 氛围 | ④ 衰减 | 不追求留存，追求余味 |
| 作品集 / 游戏 | ⑤ 循环 | 让用户自己找峰值 |

### 张力标注法

在幕表上给每幕打一个 0–10 的张力值，然后画出来看形状：

```
幕:   01 02 03 04 05 06 07 08 09 10
张力:  3  5  4  6  5  8  7  9  6 10
                        ↑        ↑
                     宣言幕    破坏幕
```

**规则**：
- 相邻两幕张力差 ≥ 2 才有"推进感"
- 不允许连续三幕同值
- 峰值幕不超过 2 个（多了就没有峰）
- 最后一幕张力不能是 0（否则"没结束感"），但也不能是 10（否则"没落地感"）

## 三、转场类型学：转场是叙事标点

### 十种转场

| # | 名称 | 做法 | 语义 | 时长 |
|---|---|---|---|---|
| 1 | **切** Cut | 直接换 | 冲击、并列、强调 | 0 |
| 2 | **淡** Fade | 透明度 | 时间流逝、温和 | 1 拍 |
| 3 | **推** Push | 沿 Z 轴推进 | 深入、进入 | 1–2 拍 |
| 4 | **拉** Pull | 沿 Z 轴后退 | 抽离、揭示全貌 | 1–2 拍 |
| 5 | **遮** Wipe | 几何遮盖 | 章节切换、翻页 | 1 拍 |
| 6 | **光** Iris | 光圈开合 | 视角切换、凝视 | 2 拍 |
| 7 | **碎** Shatter | 画面裂解 | 破坏、终局、失控 | 2–3 拍 |
| 8 | **穿** Match | 前后景同构衔接 | 连续、一镜到底 | 1 拍 |
| 9 | **变** Morph | 形体连续变形 | 同一物的不同形态 | 2–4 拍 |
| 10 | **闪** Flash | 过曝一帧 | 顿悟、爆点 | 1/8 拍 |

### 选型原则

- **全片只用 3–4 种**。用满十种 = 没有语法。
- **主转场只一种**，其余为变体。样本 B 主转场是「光」（`iris-burst` / `iris-ring` / `iris-intro__eye`），因为它要服务"眼睛 / 角色"这个母题。
- **转场要与内容同构**：讲玻璃就用「碎」，讲凝视就用「光」，讲流水线就用「穿」。

### Iris 转场实现（样本 B 同款）

```js
// 用 clip-path 做光圈，成本低、不吃 GPU、可被 CSS 变量驱动
function iris(el, { from = 0, to = 100, ms = 1379, ease = 'cubic-bezier(.7,0,.2,1)' } = {}) {
  el.style.clipPath = `circle(${from}% at 50% 50%)`;
  el.style.transition = `clip-path ${ms}ms ${ease}`;
  requestAnimationFrame(() => { el.style.clipPath = `circle(${to}% at 50% 50%)`; });
}
```

## 四、缓动命名系统：把曲线变成设计资产

样本 B 的 CSS 里有 `--ease-snap` / `--ease-swift`，样本 C 有 `--judge-duration`。
**命名缓动 = 全站动效同源 = 观感统一。**

### 六条基础曲线

```css
:root {
  --ease-linear:  linear;
  --ease-out:     cubic-bezier(0.16, 1, 0.3, 1);      /* 进入：快起慢收 */
  --ease-in:      cubic-bezier(0.7, 0, 0.84, 0);      /* 退出：慢起快收 */
  --ease-inout:   cubic-bezier(0.65, 0, 0.35, 1);     /* 位移：对称 */
  --ease-snap:    cubic-bezier(0.2, 0, 0, 1);         /* 机械：极快到位 */
  --ease-swift:   cubic-bezier(0.4, 0, 0.2, 1);       /* 通用：Material 标准 */
  --ease-overshoot: cubic-bezier(0.34, 1.56, 0.64, 1);/* 弹性：有回弹 */
}
```

### 使用规则

| 场景 | 曲线 | 理由 |
|---|---|---|
| 元素入场 | `--ease-out` | 快起，抓注意力 |
| 元素退场 | `--ease-in` | 慢起，不抢戏 |
| 相机移动 | `--ease-inout` | 对称，无顿挫 |
| UI 按钮反馈 | `--ease-snap` | 机械感，响应快 |
| 弹窗 / 卡片 | `--ease-overshoot` | 有生命感 |
| 持续旋转 / 呼吸 | `--ease-linear` | 不能有加速度 |

**硬要求**：全站自定义缓动 ≤ 6 条。第 7 条开始一定是重复造轮子。

## 五、镜头语法：五类镜头 + 一条铁律

### 五类镜头

| 类型 | 描述 | 用途 |
|---|---|---|
| **建立** Establishing | 全景、高机位、慢推 | 开场、换场 |
| **主体** Subject | 中景、3/4 侧、浅景深 | 展示细节 |
| **特写** Detail | 近景、微距、浅景深 | 材质、质感 |
| **主观** POV | 第一人称、手持微抖 | 沉浸、紧张 |
| **环绕** Orbit | 绕物体、匀速 | 展示全貌、收尾 |

### 一条铁律：一幕一镜

**同一幕内不允许切镜。** 切镜 = 换幕。
理由：切镜会重置用户的空间认知，而一幕的功能是"完成一个动作"，动作被切断就不成立。

### 机位推导（不是拍脑袋）

```js
// 由物体包围球反推机位，保证"装得下 + 有留白"
function frameCamera(camera, box, { fill = 0.62, azimuth = 35, elevation = 18 } = {}) {
  const sphere = box.getBoundingSphere(new THREE.Sphere());
  const r = sphere.radius;
  const vFov = THREE.MathUtils.degToRad(camera.fov);
  const hFov = 2 * Math.atan(Math.tan(vFov / 2) * camera.aspect);
  const dist = r / Math.sin(Math.min(vFov, hFov) / 2) / fill;
  const a = THREE.MathUtils.degToRad(azimuth);
  const e = THREE.MathUtils.degToRad(elevation);
  camera.position.set(
    sphere.center.x + dist * Math.cos(e) * Math.sin(a),
    sphere.center.y + dist * Math.sin(e),
    sphere.center.z + dist * Math.cos(e) * Math.cos(a)
  );
  camera.lookAt(sphere.center);
}
```

`fill` 的取值语义：
- `0.45` 大量留白（品牌、氛围）
- `0.62` 标准（产品、展示）
- `0.80` 充满（细节、压迫）
- `0.95` 溢出（特写、紧张）

## 六、时间预算表

一个 60 秒的体验，时间应该这样花：

| 段 | 占比 | 60s 实例 | 说明 |
|---|---|---|---|
| GATE 门槛 | 3–5% | 2–3s | 越短越好，但必须存在 |
| ONBOARDING 引导 | 5–8% | 3–5s | 一句话 + 一次示范 |
| JOURNEY 旅程 | 60–70% | 36–42s | 主体 |
| CLIMAX 高潮 | 8–12% | 5–7s | 最贵的一段 |
| RESOLUTION 收束 | 8–12% | 5–7s | 不能急刹 |
| REMNANT 痕迹 | 3–5% | 2–3s | 分数 / 生成物 / 一句话 |

**常见错误**：把 80% 时间花在 JOURNEY 的建模上，CLIMAX 只有 1 秒。观众记不住。

## 七、进度可见性

用户必须随时知道"我在哪、还有多久"。

### 三种进度表达

| 类型 | 适用 | 实现 |
|---|---|---|
| **显式数字** | 加载、线性流程 | `Loading... 42%` |
| **章节点** | 多幕体验 | 底部 10 个点，当前高亮 |
| **空间隐喻** | 沉浸式 | 场景本身在推进（走廊、电梯、隧道） |

样本 B 用**空间隐喻**（十幕 = 十个空间站），样本 A 用**显式数字**，样本 C 用**街机分数条**。

### 反模式

- 进度条走得比实际慢（欺骗感）
- 进度条走完但还要等（信任崩塌）
- 没有进度（焦虑）

**规则**：进度条到 100% 时，画面必须已经可用。

## 八、reduced-motion 不是可选项

```js
const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
```

开启时：
- 所有转场时长 ×0.25（不是 0，0 会失去空间连续性）
- 取消视差、抖动、过曝闪烁
- 保留状态变更的**颜色/透明度**提示
- 若内容依赖运动表达（如"按住跳舞"），提供**静态替代幕** + 文字说明

**硬要求**：`reduced-motion` 下体验仍能走完六段式。走不完 = 设计缺陷，不是无障碍问题。

## 九、提示表要能被机器验（`timeline_check.py`）

上面七节讲的是**怎么设计**时间轴。这一节讲**怎么证明设计没写错**——
因为提示表最常见的三种死法全是静态可查的：

| 死法 | 症状 | 为什么难查 |
|---|---|---|
| 多时钟 | 切标签页后卡节拍的东西散了 | 没有单一「当前时间」可以打印出来看 |
| 覆盖空洞 | 第 3 幕到第 4 幕之间画面定格 | 看起来像卡死，实际是没人负责 |
| 缓动缺失 | 全线性，读起来像机械臂 | 单帧看不出，整段才显得廉价 |

把提示表写成**纯数据文件**，就能在交付前用脚本钉死：

```json
{
  "duration": 122.0,
  "master_clock": "audio",
  "reduced_motion": "skip-transitions",
  "quality_tiers": {
    "LOW":  {"tessellation": 4, "blurSteps": 3, "chromaticSteps": 6,  "textureSize": "1k"},
    "HIGH": {"tessellation": 7, "blurSteps": 5, "chromaticSteps": 24, "textureSize": "4k"}
  },
  "cues": [
    {"t": 0.000, "id": "fade-in", "dur": 5.0, "ease": "outQuad", "apply": "exposure"}
  ]
}
```

```bash
python3 scripts/timeline_check.py timeline.json --strict
```

13 条规则分三类：

| 类 | 规则 | 级别 |
|---|---|---|
| 结构 | T01 形状 / T03 必备字段（id、t） / T06 id 重号 | 硬错误 |
| 时间 | T02 主时钟未声明 / T07 越过总时长 / T04 缓动未登记 | 硬错误 |
| 时间 | T09 覆盖空洞 / T10 节拍不整除 / T11 cue 不在节拍网格 | 警告 |
| 质量 | T13 降级只改像素比 / T14 无 reduced-motion | 警告 |

**为什么「主时钟未声明」是硬错误**：本章讲的 BPM 栅格、张力曲线、转场
全部建立在「有一个统一的当前时间」之上。时钟不唯一，后面所有设计都失去意义。

**为什么「降级只改像素比」只是警告**：有些场景确实只靠像素比就够了；
但默认应当怀疑——只改 `devicePixelRatio` 不降算法复杂度，弱机照样卡。

配套骨架 `assets/scaffold/experience-shell.html` 就是按这套契约写的，
它同时要过 `validate_scene.py`（三维站不站得住）与 `validate_experience.py`
（体验成不成立）两把尺子。
